# 作废清单

本清单收:试过后放弃的做法。种子与模板不许再把它们写成规矩;种子正文里不许出现下面任何一个关键词。

### 1. 判卷与复检两道都走

关键词:判卷与复检两道都走|判卷复检两道都走
**为什么放弃:** 想让每张单在执行方之外再过「总监逐单判卷」与「独立复核」两层外部把关;把关在总监那儿排队成了真瓶颈,而交付责任已收到模块的 0 号窗一人身上,外部两道不再增加信息量,只增加往返。
源案例:2026-09-15 某项目逐单判卷在总监处排队,设计者当窗定两个模块剩下的活不再过复检和判卷,出了问题由 0 号员工负责,改由各自 0 号窗并线上线,当夜两个模块全部上线,于是放弃。

### 2. 每单默认走独立复检

关键词:每单默认走独立复检|每单默认复检|默认独立复检
**为什么放弃:** 想在施工与验收之外常设一个独立复核的岗位,每张单上线前都再核一遍;实测它抓到的多是文书小问题,同一批数在几份件里重复抄写,改为每单只跑一道事后审计。审计报了漏做、或用户看得见的面时一次性临时加的独立核对,以及 0 号窗另起干净子代理做的独立核对,都不在此列。
源案例:2026-09-25 某项目流程扫盘:六份审计无一次判返工,一份收口报告 57,614 字 13 节、与审计件和决策草稿三处重复,于是放弃默认复检,改成一道事后审计。

### 3. 员工侧跑变异测试

关键词:员工侧跑变异测试|每单跑变异测试
**为什么放弃:** 想让执行方向一个不能自己改代码的把关人证明测试真能抓错;把关人撤掉后这个前提就没了,它却照样吃掉执行方大半额度。改闸本身的单仍要故意改坏一次、证明闸拦得住,那是另一回事。
源案例:2026-09-15 夜某项目设计者说员工八成额度浪费在变异测试、三趟复现和持久化回归上,保持这三样任务就不可能完成;次日统计 182 张任务书里 104 张要求变异测试,于是放弃。

### 4. 测试跑三趟复现

关键词:测试跑三趟复现|三趟复现
**为什么放弃:** 想让执行方向把关人证明测试结果稳定可复现;把关撤了就是纯重复,而且同一个词在任务书里又被当成多次采样测量的要求,一处是要求、一处是禁令,双方对不上。排查非确定性时在干净树上连跑两次对照,是另一回事。
源案例:2026-09-16 某项目 182 张任务书里 110 张要求三趟复现;同日一张书里「三趟」既是采样测量的要求又是测试禁令,执行方被质疑做错,查明是措辞撞车,于是放弃。

### 5. 员工侧跑持久化往返回归

关键词:员工侧跑持久化往返回归|员工侧持久化往返
**为什么放弃:** 想让每个执行方各跑一遍依赖数据库的往返回归来自证;并线端最终组合树的全量测试已经兜住,人人再跑一遍只是给已撤掉的把关人交作业。
源案例:2026-09-15 夜某项目设计者当面否掉「下游员工也该跑测试以便分责」的提议,定员工侧不做持久化回归这类自证,理由是交付有问题由 0 号窗担责、员工八成额度正浪费在这几样上,于是放弃。

### 6. 收尾问答十几项

关键词:十几项收尾问答|收尾问答十几项
**为什么放弃:** 为判卷人准备的形式性收尾题,把关撤掉后只剩重复,改成收尾只留三问(怎么打开它 / 最没把握的一处 / 自主假设)。
源案例:2026-09-21 某项目设计者定 0 号任务书里给把关人准备的复检测试全砍,十几项收尾问答压成三问,当天第一张按此写法的书落地执行,于是放弃。

### 7. 证据图压到限定体积

关键词:证据图压到限定体积|证据图压到固定字节
**为什么放弃:** 把证据图压到固定字节数,是为了方便外部把关人翻看归档;把关人撤了就没有读者,改为不压缩,只保留母版完整留存与从登记目录开原图核对。
源案例:2026-09-16 某项目按模块定验证口径,美术类不再要求压图、只保母版与登记目录两项;09-21 复检测试全砍时压图又一并列进不做清单,于是放弃。

### 8. 员工侧写前端单元测试

关键词:员工侧写前端单元测试|员工侧前端单测
**为什么放弃:** 单元测试结构性地看不到渲染层,而前端问题多出在那一层;把关撤了之后它只剩成本,改为编译通过加真实环境里走一遍。
源案例:2026-09-21 某项目设计者定下前端的单测也可以砍掉,前端类单从此只要求编译通过加实机走查,于是放弃。

### 9. 执行方做审美自检

关键词:执行方做审美自检|审美自检
**为什么放弃:** 想让 AI 先替设计者把一道审美关;AI 自审过关的产出,设计者实机一看仍整批返工,审美只能由设计者或专业美工判,规格与审美压在同一个执行方身上还会混着判。
源案例:2026-09-23 某项目一批三万八千多帧在批量授权下已过 0 号窗与子代理的审美自检并全部产出,设计者实机看后整批喊返工,于是放弃。

### 10. 每轮重测性能基准

关键词:每轮重测性能基准|每轮都重测基准
**为什么放弃:** 大规模性能基准要占设计者本人的设备与屏幕;已测过、这一轮又没动相关结构时,重测只是浪费,改为只在首次上真链路或相关结构大改时测一次。
源案例:2026-09-23 某项目一张进行中的单的任务书里又写了一条 500 实例基准判据,设计者指出配套的样例早已测过这一规模,追问是谁安排每一轮都测试,查明是总监按章程条款自行加进判据、并非他要求,于是放弃。

### 11. 逐项截图取证

关键词:逐项截图取证|每处改动都截图取证
**为什么放弃:** 每处改动都启动客户端截图,时间成本极高、截图链路本身还有缺陷,而设计者本来就会拿最终产物自己验;改为整批只留一张总览,静态判据照旧是主判据。
源案例:2026-09-21 某项目先定「免客户端取证,整个流程最多 1 次」,当夜设计者又说取图不重要、浪费他的 token,一个批次取一张大界面就可以,于是放弃。

### 12. 高自主档遇阻就停车

关键词:高自主档遇阻就停车|缺列举就停车
**为什么放弃:** 想让执行方不擅自决定;高档执行方能做的都做完了还在空等答案,时间被停车条款本身吃掉,真要严管就降档,不在高档书里加停车条款。
源案例:2026-09-12 某项目两张高自主档单按旧规在「等四个问题的答案」上停了很久,设计者当场改为先做完再汇报、有问题再返工,于是放弃。

### 13. 任务书堆砌禁令

关键词:任务书堆砌禁令|禁令堆砌
**为什么放弃:** 想靠条数把执行方框住;禁令一多,执行方把它们当繁文缛节,真正致命的几条反而被淹没,给理由比给条数管用。
源案例:2026-09-14 某项目设计者指出通用任务书对高档员工限制太多,他们要的是效率,参数冲突时得有权当场修改,当天把「一堆不许」改成一节授权、只留三条违反即出事故的硬红线,于是放弃。

### 14. 任务书整段抄规格

关键词:整段抄规格|整段复制规格
**为什么放弃:** 把参考规格与通用条款整段抄进每张书,长文挤掉高档执行方稀缺的上下文,本单特有的判据反被淹没;改为规格给路径、通用段引模板。
源案例:2026-09-15 某项目一次派出十几张任务书、每张 27~29KB、通用条款占约六成,设计者看完回复写得太详细了,于是放弃。

### 15. 返工要求只写进判语

关键词:返工要求只写进判语|返工要求只写在判语
**为什么放弃:** 重开的执行窗只读任务书,读不到判语,同一件活照原文空转;返工要求必须写进任务书,或走能送达在跑会话的实时对话通道。
源案例:2026-09-05 某项目一条返工要求只写在判语里,同一张单空转两轮、第二次仍照原文再做一遍,设计者当面把要求递给执行方才一次做对,于是放弃。

### 16. 一人做得完的活按岗位拆

关键词:一人做得完的活按岗位拆|按岗位拆给几人
**为什么放弃:** 一个执行单元做得完的活,拆给几个岗位的唯一收益是归属清楚,代价是多次交接、多次开窗、多次把关,对设计者全是额外等待;拆不拆只看一个执行单元做不做得完。一个单元装不下时按阶段续接,或从主控岗开出临时顾问位分担上下文,都不在此列。
源案例:2026-09-12 某项目一个只是切换视角的需求被拆给两个岗位、两张配套单分别做,设计者当场纠正合并成一张由同一执行单元从头做到尾,于是放弃。

### 17. 主控窗亲手读码写码

关键词:主控窗亲手读码|主控窗亲手写码
**为什么放弃:** 主控窗自己读写码,窗被文件撑满,后面的判断变成回忆而不是读到的事实,是幻觉的来源;主控窗的上下文要留给和设计者的沟通。设计者当窗明令临时放宽时照做、把读写压到最小,不在此列。
源案例:2026-09-23 某项目一扇 0 号窗被临时放宽成亲手写代码,写了九处后窗里文本变大,设计者当场收回:写代码也要交给子代理,否则窗里文本一大就会幻觉,于是放弃。

### 18. 总监逐个员工写任务书

关键词:逐个员工写任务书|逐员工写书
**为什么放弃:** 谁写详细书谁就得为它担责,而交付责任已收在 0 号窗一人;总监逐个员工写书既重复了 0 号窗的活,又把切法写死。
源案例:2026-09-16 某项目总监把一个模块切成七张每张 27KB 的员工任务书,设计者点明总监的产出应是给 0 号窗的一张需求单、定责天然收在 0 号窗,于是放弃。

### 19. 照抄被检方总结当结论

关键词:照抄被检方总结|转述被检方总结
**为什么放弃:** 转述被检方自己的总结不代表核过,抄被检方那棵树等于没检;核的一方要另起、自己看证据。
源案例:2026-09-16 某项目一次试跑里两种收法摆在一起:照抄被检方的总结只得一句「全部测试通过」,0 号窗自己核则查实了四项关键结论(其中两项是设计者点名的硬约束);09-19 设计者以防幻觉为由收紧口径,同批定下核验类子任务必须独立发起、不复用被检方的结论,于是放弃。

### 20. 基线不过的绝对相等判据

关键词:基线不过的绝对相等判据|集合完全相等当判据
**为什么放弃:** 要求两边集合完全相等的判据,连未改动的基线自己都过不了,等于一道谁也过不去、只能被绕开或放宽到恒真的假闸;改成以基线为准、差额不许扩大。两棵树的用例清单求差集、要求新增为零,不在此列。
源案例:2026-09-20 某项目一批活的一条判据原定两种语言的键集合完全相等,实测基线本来就不相等,该批主动改成「差额不许扩大」并写进交接件,于是放弃。

### 21. 只读障碍逐处放行

关键词:只读障碍逐处放行|逐处放行
**为什么放弃:** 放行是单向的,只解决眼前这一处,下一处立刻又撞上,每次一整轮往返;第二次撞上就说明是结构性问题,该自己跑探针拿全貌。
源案例:2026-09-12 某项目一张单连续逐处放行四次,执行方每次都正确停车,第四次改为自己打补丁跑探针,三次探针就查清是结构性问题、当场改为拆单,于是放弃。

### 22. 交付项写绝对路径

关键词:交付项写绝对路径|交付项用绝对路径
**为什么放弃:** 交付检查按「建单时的当前目录 + 路径」核存在,而工作树按治理规则在合并后 7 天内回收,写成绝对路径的交付项到那时会失效,后来的核对方也用不了;交付项一律写仓内相对路径。
源案例:2026-09-06 某项目五张单用绝对路径写交付项撞了三张,活做完却交不了;09-20 又实测建单时的当前目录决定核不核得到路径,系统只警告不拦,当时判断不该为消警告改写绝对路径,因为按治理规则工作树合并后 7 天内回收、路径会失效,于是放弃。
