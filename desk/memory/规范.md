# 记忆与换窗接管规范

版本 v1.0 · 2026-09-25。本文件是 `desk/memory/` 的格式真源:记忆文件、记忆索引、换窗三件套(总编换窗归档 / 总监接管件 / 0 号交接件)、种子分节文件、作废清单,一律按这里写。模板在 `desk/memory/模板/`,折叠脚本是 `desk/memory/fold_index.py`。

名词:**设计者** = 拍板的人;**总编** = 统管全局的 AI 窗;**总监** = 管一个位(一块业务)的 AI 窗;**0 号窗** = 为一张单新开的员工窗,只派单、验收、并线,不亲手写代码;**子代理** = 窗里派出去干具体活的代理;**换窗** = 旧窗上下文用尽或收工,开新窗接着干。

目录:§1 记忆放在哪 · §2 单文件单事实与 frontmatter · §3 正文三段与样例 · §4 索引 MEMORY.md · §5 超限折叠 · §6 写入、更新、删除纪律 · §7 换窗接管 · §8 种子分节文件格式 · §9 作废清单格式 · 附 设计者亲测步骤

## §1 记忆放在哪

- **位置**:Claude Code 的自动记忆目录 `~/.claude/projects/<项目 slug>/memory/`。`<项目 slug>` 由开窗时的工作目录路径生成(例:`D:\demo` → `d--demo`);换一个目录开窗,就是另一套记忆。
- **自动载入**:目录下的 `MEMORY.md`(索引)每次开窗整份进上下文;其余记忆文件不自动载入,窗按索引里的链接按需去读。所以索引要短、一行一条,细节放进各自的记忆文件。
- **三处「记忆」是三件事,别混**:

| 载体 | 在哪 | 管什么 | 谁写 |
|---|---|---|---|
| 自动记忆 | 上面的 memory 目录 | 跨窗复用的规矩与教训、指向接管件的指针 | 总编管索引;各位只加自己的行 |
| 换窗归档 / 接管件 | 办公仓 `<办公目录>/<位名>/` | 本位此刻的现状与下一步 | 总编、总监各写各的 |
| 0 号交接件 | 办公仓 `<办公目录>/<位名>/任务书/` | 一张单做到哪、下一棒从哪接 | 子代理起草,0 号只核 |

员工窗的「工位记忆」不再使用,见 §7.6。

来由:2026-09-14 某大型多人在线项目盘点记忆体积,前三大全是总编、总监的接管件和流水账(104KB / 87KB / 42KB),员工工位记忆全项目才 37KB;三处东西混着都叫「记忆」,谁该压缩、谁该保全说不清,于是分开。

## §2 单文件单事实与 frontmatter

- **一个文件只记一个事实**(一条规矩、一个教训、一个指针)。两件事就两个文件、索引两行。
- **文件名** = `<name>.md`;name 是短横线连接的小写英文 slug(例 `memory-index-hard-limit`),全目录唯一。
- **frontmatter 固定三项**(以 Claude Code 现行记忆格式为准,精简型):

```
---
name: <短横线小写 slug,与文件名一致>
description: <一行摘要:写「什么情况下该想起这条」,召回时靠它判相关>
metadata:
  type: user | feedback | project | reference
---
```

- `metadata:` 行尾不留空格;`type` 在 `metadata:` 下缩进两格,不写在顶层。
- 旧文件里的 `node_type`、`originSessionId`、`modified` 是历史遗留的完整型字段:新文件不写,旧文件不必回头删。
- description 一行写完;含 `: `(冒号加空格)或以 `-`、`[`、`"` 等符号开头时,整句加双引号。

**四类怎么判**(按顺序问,第一个「是」就定):

| 先问 | 是 → type | 装什么 | 例 |
|---|---|---|---|
| 1. 正文主要是「去哪里找」吗? | reference | 外部资源指针:文件路径、网址、看板、仓位置;二级入口 `*-index.md` 也归此类 | 「接管件在 `<办公目录>/总编/`」 |
| 2. 说的是人不是事吗? | user | 用户(设计者)是谁、角色、偏好、沟通习惯、知识背景;换个项目也成立 | 「设计者不读英文,回话一律中文」 |
| 3. 会过期吗?是某项工作此刻的状态吗? | project | 进行中的工作、目标、约束、截止期、谁在做什么;**相对日期一律换成绝对日期**(「下周四」→「2026-10-01」) | 「登录模块 2026-10-01 前冻结接口」 |
| 4. 以上都不是 | feedback | 用户给的纠正,以及用户认可的做法;必须写清为什么 | 「提交信息只写改了什么,不写聊天过程」 |

project 类到期就更新或删掉;feedback 类写成「以后遇到 X 就做 / 不做 Y」。

## §3 正文三段与样例

frontmatter 之后,正文按这个顺序:

1. **规则本体**:一段,或 1~6 条编号。第一句就把规则说完。
2. `**Why:**` 一段:为什么有这条;什么情况下它不再成立。
3. `**How to apply:**` 一段:什么时候用、怎么做、怎么判做对了。
4. **最后一行**以 `源案例:` 开头:哪天、撞了什么、代价多大、于是立了这条。**顶格写、不加粗、一行写完**,冒号用半角 `:`。user 类写「何时得知」(例:`源案例:2026-09-25 设计者开项目时自述`)。

说明:

- 段落标签写死为 `**Why:**` / `**How to apply:**` / `源案例:`。前两个与 Claude Code 自带记忆提示词里的 Why / How to apply 是同一个东西,工具自动写出的记忆天然合规;不要改写成「为什么」「怎么用」之类别名,否则核对命令数不齐。
- 「源案例」只要求**新写**的记忆文件带;旧库不回填(旧文件的案例多半已写在 Why 里,补一行是重复)。
- 项目自己的记忆可以写单号、提交号,方便追查;要收进种子给别的项目用时,再按 §8 抽象掉。剥了案例,下一窗就不知道这条为什么存在、什么时候可以废。

**完整样例**(`memory-index-hard-limit.md` 全文):

```
---
name: memory-index-hard-limit
description: 记忆索引 MEMORY.md 硬上限 24,000 字符(按字符不按字节);超了用 fold_index.py 整节原样折成二级入口
metadata:
  type: feedback
---

记忆索引每次开窗整份载入,超过约 24,000 字符的尾部会被截掉。往索引加行后就量一次;超了用 `desk/memory/fold_index.py` 把整节原样折成二级入口,条目一条不删。

**Why:** 被截掉的是末尾几行,恰好是最新写进去的规则;截断时窗里没有醒目报错,读的人不知道自己少读了。
**How to apply:** 量法只用 `python -c "import io;print(len(io.open('MEMORY.md',encoding='utf-8').read()))"`;余量不足 3,000 字符就主动折;判断有没有被截,只比「自己上下文里的索引末行」与 `tail -1 MEMORY.md`。
源案例:2026-09-17 某大型多人在线项目的索引涨到约 24,950 字符,开窗加载提示末尾 2 行被截,被截的正是当天新立的两条规则;压回约 24,370 字符后末行复原;09-19 两个窗同日再撞,当天连折两节降到约 18,300 字符,于是定 24,000 硬上限与整节折法。
```

## §4 索引 MEMORY.md

- **不带 frontmatter**:它是开窗自动整体载入的目录页,第一行就是第一个 `## ` 节标题。
- **分节**:用 `## <节名>` 分主题。节名定了少改——折叠按节名定位,二级入口文件名也可能由节名生成。
- **行格式**:一条一行,`- [标题](文件.md) — 一句钩子`。
  - 标题 ≈ 规则本身,一眼看出说的是什么;钩子写「什么时候该想起它」和关键日期。
  - 可在 `[` 前加 ★ 标重要度(最多三颗);一行只挂一个链接。
  - 单行建议 ≤200 字符(软限);细节进记忆文件,不塞进索引。
- **硬上限 24,000 字符**,按字符计,不按字节。唯一量法:

```
python -c "import io;print(len(io.open(r'<记忆目录>/MEMORY.md',encoding='utf-8').read()))"
```

- `wc -c` 是字节数:中文为主的索引,字节约是字符的 1.6~1.7 倍,会把没超的误报成超了。
- `wc -m` 在 C locale 下(Git Bash 里 LANG / LC_ALL 为空时常见)会退化成字节数,**不可信**。
- 按字节算阈值的自动提醒一律不作数,只认上面这条量法。
- **判有没有被截断**:只比「自己上下文里看到的索引末行」与 `tail -1 <记忆目录>/MEMORY.md`,两者不一致才是被截了。开窗加载时提示有行被截掉,当场按 §5 折。
- **谁维护**:索引归总编管;总监、0 号只加(或删)自己那一行;超限由总编折。
- **接管指针**:每位在索引里最多一行,指向自己的接管指针文件(§7.3)。

来由:2026-09 同一项目,本机 Git Bash 的 locale 变量全空,`wc -m` 按字节报数;写文件后的自动提醒钩子先后几次把字节当字符报超限,照着提醒去「合并或丢弃条目」就是跨位删别人的入口;真正的截断反而要靠比末行才发现。

## §5 超限折叠(fold_index.py)

**何时折**

- 余量不足 3,000 字符(即超过 21,000)就主动折,别等被截。
- 开窗加载提示有行被截掉,当场折。
- 二级入口自己也适用 24,000 硬上限(见本节末)。

**折哪节**

- 自己挑:选内容稳定、不必每窗都看的节,用 `--section` 指定。每窗必读的节(如接管指针那一节)不折。
- 赶时间:`--auto` 从最大的节起逐节折,直到 ≤ limit。

**用法**

```
# 0. 先把原件备份到记忆目录外
cp <记忆目录>/MEMORY.md <目录外>/MEMORY.before-fold-<YYYY-MM-DD>.md
# 1. 演练:只算、只核、只报告,不写文件
python desk/memory/fold_index.py <记忆目录>/MEMORY.md --section "<节名>" --slug <英文-slug> --dry-run
# 2. 正式折(--section 与 --slug 可重复,按先后一一配对)
python desk/memory/fold_index.py <记忆目录>/MEMORY.md --section "<节名>" --slug <英文-slug>
# 或:自动从最大节折起
python desk/memory/fold_index.py <记忆目录>/MEMORY.md --auto --limit 24000
# 脚本自测:生成约 30,000 字符的假索引跑一次 --auto 并断言
python desk/memory/fold_index.py --selftest --out <空目录>
```

**脚本做什么**

1. 按 `## ` 行定位节;节体到下一个 `# ` 或 `## ` 标题为止(代码围栏里的不算标题)。
2. 节体(去掉首尾空行)原文逐字搬到同目录 `<slug>-index.md`:文件不存在就新建,带 frontmatter(`type: reference`)和 `# <节名>` 标题;已存在就原文追加到末尾。
3. 原位保留 `## ` 标题,节体换成一行入口:`- [<节名>入口](<slug>-index.md) — <N> 条已折入 <日期>`。
4. slug:建议总是用 `--slug` 给一个英文主题名(看文件名就知道装的是什么)。不给时:节名全是 ASCII,就转成小写、非字母数字连成一个短横线;节名含中文,就用 `section-<节名 UTF-8 的 sha1 前 8 位>`——同名节永远得到同一个 slug,与节的先后无关。
5. 折过又长出新条目的节:节首那几行已指向同一个二级入口的旧入口行留在原位,只搬后面的新行,新入口行加在旧入口行下面。
6. 带 BOM 或 CRLF 的文件拒收(先转成无 BOM、LF 再折)。

**条目守恒**:条目 = 以 `- ` 顶格开头的行。缩进子项、`### ` 小标题、说明文字不算条目,但照样逐字搬。

```
折前主索引条目数 = 折后主索引条目数 - 新增入口行数 + 本次搬入二级入口的条目数
```

脚本另核三样:每个被搬行在二级入口里逐字存在;把入口行换回被搬块,能逐字还原折前全文;二级入口原有内容一字不动。任一不过:不写任何文件、退出码 1、打印原因。先写临时文件,全部核过再原子替换,写完回读再比一次。报告打印折前 / 折后字符数、limit、折了哪几节、各节搬了几条、守恒式左右两边,最后一行固定是 `末行: <折后索引最后一行>`。

**折后自核三步**(不信脚本也能自己验):

1. 量字符:用 §4 的 python 量法 → 必须 ≤ 24,000。
2. 比末行:`tail -1 <记忆目录>/MEMORY.md` 与报告最后一行(去掉 `末行: ` 前缀)逐字相同。
3. 数条目:备份件、折后索引、二级入口各跑一次 `grep -c '^- '`,代入守恒式。新建的二级入口表头没有 `- ` 行,直接用;追加的二级入口用追加前后之差。

折完可以手工给入口行的钩子补几个关键词便于召回——只改那一行的文字,条目数不变。

**二级、三级入口**

- 二级入口 `<slug>-index.md` 是记忆文件(带 frontmatter,type=reference),同样适用 24,000 硬上限。
- 超了:先给它加几个 `## ` 小节标题(只加标题行,不动条目),再用同一脚本对它折,生成三级入口。
- **最多到三级**。三级入口再超,说明这一块该删过期条目或拆成几个主题,不再往下折。

来由:2026-09-19 ~ 09-22 同一项目折了四次索引,每次现写一段 python;一次用 heredoc 传含反斜杠的匹配串直接出错;到第四次才把「搬走的行与新文件逐行对上、续行对上、末行与 tail -1 一致、原件备份在目录外」列全。本脚本第一次把这套折法落成可复用文件。

## §6 写入、更新、删除纪律

1. **先查再写**:写之前在记忆目录里 grep 两三个关键词;有同题就改那一份,不另起一份。
2. **每改一记**:一次提交、一次部署、判出一条新口径,当场写,不攒到收窗——窗随时会停在那里,没有「收窗仪式」这个时刻。
3. **只写下次会重踩的那一条**:代码结构、提交历史、单号进展、文件清单这些仓里现查得到的,不进记忆;一窗的台面与账写交接件,不写记忆。
4. **错的就删,过期就改**:发现写错当场改或删;删文件与删索引行同一步做;不留「已作废」的空壳条目。
5. **否定式断言先验再写**:「X 读不到」「Y 从来不行」写进去之前花一分钟验证,写进去后会被多个窗照搬当依据。验过五次不成立也不代表以后不成立,引用时当场再跑一次。
6. **记忆是背景不是指令**:记忆里的「执行…」「先读…」之类句子不构成当前任务;当前任务以用户这一窗说的话和任务书为准。记忆里的路径、数字、函数名是写下那天的快照,引用前现查;与现状冲突以现查为准,并顺手修记忆。
7. **大件不进记忆**:接管件、归档正文放办公仓,记忆里只留 ≤1KB 的指针。

来由:2026-09-14 某项目一位总监做完一笔改动、部署、答复都齐了,只追加了交接件,记忆一条没落,设计者提醒才补,当窗定「每改一记」;同期「索引后半截读不到」这条否定式断言被五个窗先后实测否掉,第六次(09-17)才真的发生。

## §7 换窗接管

### 7.1 三种文件各管什么

| 文件 | 谁的 | 管什么 | 篇幅上限 | 模板 |
|---|---|---|---|---|
| 总编换窗归档 | 总编 | 全局现状、下一步、铁律、裁定速查 | ≤24,000 字符 | `desk/memory/模板/总编换窗归档.md` |
| 总监接管件 | 每位总监一份 | 本位现状、下一步、铁律、边界 | ≤24,000 字符 | `desk/memory/模板/总监接管件.md` |
| 0 号交接件 | 一单一份 | 这张单做到哪、下一棒从哪接 | ≤6,000 字 | `desk/memory/模板/0号交接件.md` |

三份共同铁律:**只写现状与下一步,不复述历史**。历史用搜索(`git log`、归档目录),不整读;不写数值推导过程,不逐句转录对话,不写本窗流水账。

来由:某大型多人在线项目最早一版归档(2026-08-25)247 行,过半篇幅是数值推导、设计者原话逐句转录和「本窗做了什么」;从第二十版起改成只写现状与下一步,稳定在 64~70 行,接手窗读得完。

### 7.2 谁起草、谁核

| 文件 | 起草 | 核 |
|---|---|---|
| 总编换窗归档 | 总编本窗(上下文已很大时派子代理起草) | 总编本窗 |
| 总监接管件 | 总监本窗(同上) | 总监本窗 |
| 0 号交接件、收口报告 | **子代理** | **0 号本体只核**:哈希用 git 核、数字用命令核、文件名用 ls 核;本体不重写正文 |

- 收口时要读的大件(>50KB 的对账表、进度件)只准子代理读,本体只收结论。
- 核的结果写进交接件末尾「核对记录」:命令与输出原样贴,不写「已核」两个字了事。

来由:2026-09-19 前后某项目一张单的第三棒:子代理写的代码全对,0 号本体在收口时读 410KB 对账表加 72KB 进度件,上下文涨到约 700K,写出的交接件文件名、字段、落位全错,下一棒被带偏;事后派只读子代理查明代码面全对、错全在收口件,于是定「子代理起草、本体只核」。

### 7.3 命名与重写方式

| 文件 | 放哪 | 命名 | 怎么更新 |
|---|---|---|---|
| 总编换窗归档 | `<办公目录>/总编/` | `换窗归档_第<N>版.md` | **版号滚动**:活页只有一份;换版时写第 N+1 版新文件,旧版整份移入 `<办公目录>/总编/归档旧版/`;活页里不追加历史 |
| 总监接管件 | `<办公目录>/<位名>/` | `接管件.md`(固定不改名) | **整份重写**:每次换窗重写全文、只写现状;重写前旧版整份移入 `<办公目录>/<位名>/归档旧版/接管件_<YYYY-MM-DD-HHMM>.md`;不往后追加「之 N」段,不在顶上堆「本轮先读这段」 |
| 0 号交接件 | `<办公目录>/<位名>/任务书/` | `<单号>_交接件.md` | **一单一份,做不完才写**;做完了写收口报告(§7.7),不写交接件;同一单再次交接就整份重写 |

**记忆里的接管指针**:每位在记忆目录里一个 reference 类文件(例 `editor-handoff-pointer.md`),正文只有「当前件的路径 + 一句话」,≤1KB;换版或重写后改那一行路径,不在指针文件里追加「某日补」段。索引里对应一行:`- [<位名>接管指针](<文件>.md) — <当前版号或日期>`。

来由:某大型多人在线项目三种写法并存:一位总监的接管件用「九之一 … 九之十四」一路往后追加,接手人只能「认末尾最新段」;另一位把新段顶插、旧段标「沿革」不删,单文件涨到 519 行;还有一位在顶部放「入口路由」指向外部日期文件,2026-09-14 换手时忘了改路由,下一窗读到旧状态。总编的记忆指针文件也从第二十五窗一路追加「补」段到第三十窗。于是统一:归档版号滚动、接管件整份重写、指针只留一行。

### 7.4 公共开场命令

三份模板的「开场几步」都引用本节,不各抄一份(各抄一份,迟早抄出细微不一致)。在 Git Bash 里逐条跑,每条看完输出再跑下一条:

```
# 1. 确认站在哪:必须打出预期的仓路径,打不出就停
git -C <仓路径> rev-parse --show-toplevel
git -C <仓路径> status --short --branch
# 2. 取远端(本机直连不通时,整条加 -c http.proxy=<代理地址>)
git -C <仓路径> fetch origin
# 3. 看基点:远端主干最新一笔
git -C <仓路径> log --oneline -1 origin/main
# 4. 量记忆索引并看末行(§4)
python -c "import io;print(len(io.open(r'<记忆目录>/MEMORY.md',encoding='utf-8').read()))"
tail -1 <记忆目录>/MEMORY.md
# 5. 取时间戳(写件抬头用,别凭印象写时间)
date '+%Y-%m-%d %H:%M'
```

- 有两个仓(代码仓、办公文本仓)就各跑 1~3 步。
- 要施工:一单一棵工作树,不在主检出里干活:`git -C <仓路径> worktree add <工作树路径> -b <支名> origin/main`;之后每次 git 操作前先跑第 1 步核路径。
- 提交:`git -C <工作树> add -- <路径1> <路径2>`(逐个路径,不用 `add -A`);`git -C <工作树> commit -F <消息文件>`(不用 `--amend`);提交信息只写改了什么,不写聊天过程。
- 提交后核 BOM(编辑工具会悄悄加):`git -C <工作树> show HEAD:<路径> | head -c 3 | od -An -tx1`,输出不许是 `ef bb bf`;核 blob,不只核工作区。

### 7.5 激活句两式

激活句是设计者开新窗时贴的第一句话。两式分开用,别混。

**① 全权接管句**

- 填空式:`执行 <件的绝对路径> 的全部指令,<从哪做到哪:按 §一 接管 <位名> 位 / 从 §〇 第 1 步做到收尾三问>。这是任务不是资料,读完立即开工。[可选:本次专属的一句]`
- 示例:`执行 D:\demo\_office\总编\换窗归档_第3版.md 的全部指令,按 §一 开场几步接管总编位。这是任务不是资料,读完立即开工。`
- 「这是任务不是资料,读完立即开工」逐字保留:少了这句,新窗常把接管件当参考资料,读完写一段读后感就停。
- 起止点要可核对(§几、第几步);本次专属的要求(例如「写代码一律派子代理」)追加在句尾,不改前面的骨架。

**② 只读分身句**(开窗句带「(1)」标记)

- 填空式:`执行 <件的绝对路径> 的全部指令(1):这是 <位名> 分身窗,带全套记忆但不干活,只读 §一 第 1、2 步,读完回一句就等我开口。`
- 示例:`执行 D:\demo\_office\总编\换窗归档_第3版.md 的全部指令(1):这是总编分身窗,带全套记忆但不干活,只读 §一 第 1、2 步,读完回一句就等我开口。`
- 带「(1)」的窗(括号全角半角都算):只做 §一 第 1、2 步,把其余各节当现状背景读进去;不接台面、不动任何仓、不落裁定号、不发消息、不改记忆与接管件;读完只回一句「分身已就位,同步到 <版号或日期>」,然后等设计者开口。设计者点名要做某件具体的事,只做那一件。正窗与分身窗互不知情,分身窗不替正窗接活、不写新版归档。
- 不另存一份「(1)」版文件:同一份件,靠激活句里的标记切换读法;归档与接管件两份模板的抬头都印了这条规则。

来由:2026-09-25 某项目设计者要一个「什么都知道、但不碰台面和仓」的对谈窗,要求它保留本项目记忆、和当前窗口的记忆保持一致,只是不干活;于是在归档里加「(1)」读法,与全权接管句分开。

### 7.6 员工窗记忆清理

员工窗(0 号窗及其子代理)守四条:

1. **不继承老记忆**:每张单新开一扇员工窗;开工只读任务书(接棒时加读交接件),不读任何「工位记忆」。
2. **不把本单细节写进长期记忆**:单里的事写进任务书、进度件、交接件;确有跨单通用的教训,写成一条交给总监落。
3. **收窗时清掉本窗写入的记忆**:本窗往记忆目录写过的文件删掉、索引行删掉,同一步做。
4. **接棒只走交接件**:交接件必须自包含,接棒者不继承任何记忆也能开工。

设计者原话要点(2026-09-20):员工窗的记忆应该清理,不然会出现项目幻觉;现在每次都开新的员工窗,除非是接棒,不需要继承之前的老记忆。

来由:同日某项目把三位的 9 件员工工位记忆(最大一件 42KB)整体移入归档目录(只移不删),派单不再自动插「先读记忆」,接棒改走交接件。

### 7.7 收口报告四块

单做完时 0 号交收口报告(不写交接件):≤6,000 字,子代理起草、本体只核(核法同 §7.2),固定四块:

1. **结论一行**:做完没有、部署到哪个提交、测试新增失败数。
2. **事实段**:≤600 字,只写发生了什么,不写过程。
3. **需总监动作**:3~5 条,每条一句,写清要谁做什么。
4. **收尾三问**:怎么打开它(让人亲眼看到改动的步骤)/ 最没把握的一处 / 自主假设(自己拍板了哪些没问过的事)。

## §8 种子分节文件格式

给 `desk/memory/种子/` 下的各分节文件用。一个分节文件收一类通用经验;每一条将来展开成一个记忆文件(§2、§3),所以条目格式与记忆文件一一对应。

**文件名**:`desk/memory/种子/<n>_<节名>.md`。`<n>` 是一位数字(与本分节所属单的序号一致);`<节名>` 是中文短名,≤8 字,不含空格和 `/`。

**文件头**(从第一行起):

```
# <n> · <节名>

本节收:<一句话,本节管哪类经验>。读法:<什么时候读本节>。
```

**条目格式**(每条一个 `### ` 标题;标题下空一行写三行键值;再空一行写规则本体;最后三行固定):

```
### <n>.<k> <标题:一句话说清这条规则>

name: <短横线小写 slug,全部种子里唯一;将来就是记忆文件名>
type: <user | feedback | project | reference 四选一>
description: <一行摘要:什么情况下该想起这条>

<规则本体:一段,或 1~6 条编号>

**Why:** <为什么有这条;什么情况下它不再成立>
**How to apply:** <什么时候用、怎么做、怎么判做对了>
源案例:<YYYY-MM-DD> 某项目<撞了什么>,<代价>,于是立了本条。
```

规则:

1. 每节 ≥3 条;一条只记一个事实。
2. `name: `、`type: `、`description: `、`**Why:**`、`**How to apply:**`、`源案例:` 六种标签都**顶格**写,每条恰好各一行;冒号一律半角 `:`。
3. 「源案例」三个字只许出现在每条最后那一行的行首;文件头、说明段、规则本体、Why、How to apply 里都不许出现。
4. 源案例行一行写完,不换行;必须带 `YYYY-MM-DD` 日期;写清「撞了什么、代价、立了哪条」。user 类写「何时得知」。
5. 抽象掉一切项目专名:项目名、业务名词、单号、裁定号、分支名、远端名、人名。项目一律写「某项目」或「某大型多人在线项目」;角色写「设计者」「总编」「总监」「0 号窗」「子代理」。日期与数字保留。
6. 作废清单(§9)里的关键词一个都不许出现。

**核对命令**(对每个分节文件跑,`f` 换成文件路径。第 1 条七个数必须相等且 ≥3;第 2 条两个数必须相等;其余各条输出必须为空):

```
f='desk/memory/种子/<n>_<节名>.md'
# 1. 条目数与各标签行数:七个数相等且 ≥3
for p in '^### ' '^name: ' '^type: ' '^description: ' '^\*\*Why:\*\*' '^\*\*How to apply:\*\*' '^源案例:'; do printf '%s\t%s\n' "$(grep -c "$p" "$f")" "$p"; done
# 2. 「源案例」字样只在源案例行:两个数相等
grep -c '源案例' "$f"; grep -c '^源案例:' "$f"
# 3. 每条恰好一行源案例:输出为空
awk '/^### /{if(t!="")print t" -> "c; t=$0; c=0; next} /^源案例:/{c++} END{if(t!="")print t" -> "c}' "$f" | grep -v -- '-> 1$'
# 4. type 只许四个值:输出为空
grep '^type: ' "$f" | grep -vE '^type: (user|feedback|project|reference)$'
# 5. 源案例行带日期:输出为空
grep '^源案例:' "$f" | grep -vE '20[0-9]{2}-[0-9]{2}-[0-9]{2}'
# 6. 禁词(原项目专名与编号格式):输出为空。括号只为让本规范自身不含原词,匹配效果与不带括号相同
grep -niE '仙(侠)|xianxi(a)|T-00[0-9]{4}|D(9)-[0-9]+|hk/(main)|境(界)|法(术)|灵(石)' "$f"
# 7. name 在全部种子里唯一:输出为空
grep -h '^name: ' desk/memory/种子/*.md | sort | uniq -d
# 8. 作废关键词:跑 §9 核对命令第 2、3 条
```

## §9 作废清单格式

给 `desk/memory/作废清单.md` 用:收原项目里试过、后来放弃的做法,防止种子和模板把它们再写成规矩。

**文件头**(从第一行起):

```
# 作废清单

本清单收:试过后放弃的做法。种子与模板不许再把它们写成规矩;种子正文里不许出现下面任何一个关键词。
```

**条目格式**(每条一个 `### ` 标题;≥10 条):

```
### <k>. <做法名>

关键词:<词1>|<词2>
**为什么放弃:** <一两句:它想解决什么,为什么不划算或出了什么事>
源案例:<YYYY-MM-DD> 某项目<试了多久、撞了什么、代价>,于是放弃。
```

规则:

1. 做法名 2~12 字,说清「做什么」。
2. `关键词:` 顶格、半角冒号,多个词用半角 `|` 分隔;每个词 ≥2 字且足够具体(太泛的词会误伤正常句子);至少一个词取自做法名的核心词。
3. `**为什么放弃:**` 与 `源案例:` 顶格,每条恰好各一行;源案例行写法同 §8 规则 4、5。
4. 文件头与说明段里不许出现「源案例」三个字。

**核对命令**:

```
g='desk/memory/作废清单.md'
# 1. 前四个数相等且 ≥10;第五个数(含「源案例」字样的行数)也等于它们
grep -c '^### ' "$g"; grep -c '^关键词:' "$g"; grep -c '^\*\*为什么放弃:\*\*' "$g"; grep -c '^源案例:' "$g"; grep -c '源案例' "$g"
# 2. 抽关键词表
grep '^关键词:' "$g" | sed 's/^关键词: *//' | tr -d '\r' | tr '|' '\n' | sed 's/^ *//;s/ *$//;/^$/d' > /tmp/void-keywords.txt
# 3. 种子正文里不许出现任何关键词:输出为空
grep -nF -f /tmp/void-keywords.txt desk/memory/种子/*.md
```

## 附 设计者亲测步骤

目的:验证拿本规范与模板,在一个空目录里,上一扇总编窗定下的事能交给下一扇窗(记忆与归档一起生效,就是真实换窗的场景)。约 15 分钟,不用写代码。

**准备**

→ 建一个空文件夹:`D:\记忆亲测\`。
→ 找到本仓的 `desk\memory\模板\总编换窗归档.md`,记下它的完整路径。

**第一扇窗:写归档**

1. 在 `D:\记忆亲测\` 里开 Claude Code → 说:「你是这个空项目的总编。」
2. 跟它定三件事,越具体越好 → 例:① 项目代号叫「青石」;② 提交信息一律用中文;③ 下一步先做登录页。
3. 说:「按 <模板完整路径> 的格式,在本文件夹写第 1 版换窗归档:三件事写进 §二 现状和 §三 下一步,§一 里用不上的步骤(宪法、仓、工单台)写『无』,文末写好两种开窗句。」→ 等它写完。
4. 用记事本打开它写出的归档 → 看三件事在不在、文末有没有两种开窗句 → 复制「全权接管」那一句。
5. 关掉这扇窗。

**第二扇窗:接管**

6. 还在 `D:\记忆亲测\` 里,开一扇新的 Claude Code。
7. 粘贴第 4 步复制的那一句 → 发送 → 等它报到。
8. 问它:「上一扇窗定了哪三件事?」
9. 判定 → 三件都说对:通过 → 说错或说不出:不通过,把它的回答复制发给总编。

**加测一(可选):只测归档**

10. 目的:排除自动记忆,单测归档本身够不够用 → 另建一个空文件夹 `D:\记忆亲测_单测归档\`(换目录就读不到第一扇窗可能留下的自动记忆)→ 在里面开一扇新窗 → 粘贴同一句「全权接管」句 → 问同样的问题 → 三件都说对即通过。

**加测二(可选):只读分身**

11. 在 `D:\记忆亲测\` 再开一扇新窗 → 粘贴归档文末「只读分身」那一句 → 它应只回一句「分身已就位」就停住,不改任何文件 → 再问同样的问题,也应三件都答对。
