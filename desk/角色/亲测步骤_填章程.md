# 亲测步骤 · 30 分钟填出总编与一位模块总监的章程

> **这是什么**:给 {{拍板人}} 亲手验收角色模板的一页。拿 `desk/宪法.md` + `desk/角色/` + `desk/占位符表.md`,在一个空项目里 30 分钟内填出「总编章程」和「一位模块总监章程」。熟手照下面做约 25 分钟,留 5 分钟余量。
>
> **什么时候用**:角色模板或占位符表改过之后;或新项目开局、第一次立章程时顺手当一次验收。
>
> **怎么用**:先做完「准备」(不计时),再照分钟段一步步做,步骤用 → 串;每段末尾有自检。到点按最后一节判过不过。只准打开本页、`desk/宪法.md`、`desk/角色/` 下的模板、`desk/占位符表.md`。

## 准备(不计时)

- 建一个空目录当容器,例如 `E:/work`。随便起名,但不能建在任何 git 仓里面。
- 在容器里建 `_office/` → 进去跑 `git init -b main` → 在 `_office/` 下建两个子目录 `总编/` 与 `订单/`(下面以位名「订单」举例,换成你要激活的那一位)。
- 核 git 能提交:跑 `git -C <容器>/_office config user.name`,有输出就行;没有输出,就给这个仓配本地身份:`git -C <容器>/_office config user.name "<你的名字>"`、`git -C <容器>/_office config user.email "<邮箱>"`。也可以不配,提交时带 `-c user.name=<你的名字> -c user.email=<邮箱>`。
- 备好工具:一个能跑 `grep` 与 `git` 的命令行(如 Git Bash);一个能「在文件夹中替换」的编辑器(如 VS Code 的 Ctrl+Shift+H)。
- 想好四件事:项目叫什么;先激活哪一位、它管什么功能;宪法打算放哪(例如 `<容器>/_office/宪法.md`);总编兼不兼策划(默认兼)。

## 步骤(从打开第一份文件起计时)

**第 0~5 分钟 · 定占位符的值**

→ 打开 `desk/占位符表.md`
→ 新建一个草稿,把两份章程用到的 12 个占位符逐个写上本项目的值:
   `{{项目名}}` `{{拍板人}}` `{{生效日期}}` `{{容器路径}}` `{{办公目录}}` `{{章程目录}}` `{{代码仓路径}}` `{{代码托管远端}}` `{{远端主支}}` `{{工单台命令}}` `{{裁定簿路径}}` `{{项目章程路径}}`
→ `{{章程目录}}` 就是 `<容器>/_office`;空项目还没有代码仓,就写它将来放哪(例如 `E:/work/demo-app`);拿不准的照表里「填法示例」列的格式写一个,不求完美
→ 草稿末尾再写一行宪法路径(准备时想好的那个)
→ 自检:草稿 13 行(12 个占位符 + 宪法路径),每行都有值

**第 5~8 分钟 · 复制两份模板**

→ 打开 `desk/角色/总编.md` → 从「▼▼▼ 以下复制 ▼▼▼」下一行起复制到文末 → 存成 `<容器>/_office/总编/章程.md`(即 `{{章程目录}}/总编/章程.md`)
→ 打开 `desk/角色/模块总监.md` → 同样从「▼▼▼ 以下复制 ▼▼▼」下一行起复制到文末 → 存成 `<容器>/_office/订单/章程.md`
→ 自检:`ls <容器>/_office/总编 <容器>/_office/订单` 各看得到一份 `章程.md`

**第 8~12 分钟 · 一次换完占位符与位名**

→ 编辑器「在文件夹中替换」,范围选 `<容器>/_office`,把草稿里 12 个占位符逐个换成值(两份章程一起换,每个占位符只换一次)
→ 只在 `_office/订单/章程.md` 里,把 `<位名>` 全部换成 `订单`
→ 自检:`grep -n '[{][{]' <容器>/_office/总编/章程.md <容器>/_office/订单/章程.md` 没有输出;`grep -nF "<位名>" <容器>/_office/订单/章程.md` 没有输出

**第 12~21 分钟 · 填【填写】**

→ 在两份章程里搜【填写:…】,逐个写成本项目内容,写完连括号一起删掉
→ 总编章程 3 处:项目一句话(§一)、宪法路径(§二)、§三 开窗步骤第 5 条
→ 订单章程 6 处:本模块一句话与兼不兼策划(§一)、宪法路径(§二)、§三 开窗步骤第 6 条、平台分派规则与本位判据(§四)
→ 兼策划默认开,总编章程什么都不改;要关,照总编章程 §四「兼策划默认开」那条改
→ 四个 `##` 节名(§一 本位管什么 / §二 真源表 / §三 开窗步骤 / §四 规矩只引号)一个字不改;遇到闸号看不懂,只在 `desk/宪法.md` 里搜那一条,不整读
→ 自检:`grep -nF "【填写" <容器>/_office/总编/章程.md <容器>/_office/订单/章程.md` 没有输出;`grep -c "^## " <容器>/_office/总编/章程.md <容器>/_office/订单/章程.md` 两份都打出 4;`wc -c` 两份都不超过 6,144(按字节量,目标 ≤5,120)

**第 21~25 分钟 · 核激活句并提交**

→ 看两份章程 §三 末尾的激活句 → 把句中路径复制出来 `ls` 一次,两份文件都在
→ `git -C <容器>/_office add -- 总编/章程.md 订单/章程.md`
→ `git -C <容器>/_office commit -m "总编: 立总编与订单章程"`(准备时没配身份的,在 `git` 后面带上 `-c user.name=<你的名字> -c user.email=<邮箱>`)
→ 自检:`git -C <容器>/_office log --oneline -1` 看得到这一笔

## 30 分钟到点怎么判

计时从打开第一份文件起,到第 30 分钟整停手,看下面五条:

1. `_office/总编/章程.md` 与 `_office/订单/章程.md` 都在,并且已提交进 `_office` 仓;
2. 各段自检全部如上所写(没有输出的确实没有输出,节数确实是 4,字节数不超过 6,144);
3. 两句激活句里的路径都指向真实文件;
4. 通读两份章程,每一节都看得懂「这一位开窗后要做什么」;
5. 过程中没有打开本页开头「怎么用」列出的文件以外的东西,也没有问任何人。

五条全是「是」即**过**。超时,或任一条是「否」即**不过**:把卡住的地方记一句(哪个占位符不知道填什么、哪一节看不懂、哪条自检过不去),交总编改模板;改完换一个新的空目录重测。
