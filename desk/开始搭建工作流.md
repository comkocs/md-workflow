# 开始搭建工作流

> 这是给 AI 窗读的开局指令,不是给人看的教程。用户贴「执行 <本文件网址> 的全部指令」后,先按第 0 页分流:新项目先对接需求,接管老项目走接入向导,只装流程走建仓与起台。新项目对接成立后,再把当前目录搭成能派单的项目。
>
> 你可能是经网页摘要读到本文件的:摘要会丢命令和表格。那就先照第 0 步用 git 把 https://github.com/comkocs/md-workflow 整仓 clone 到系统临时目录,再读 `<框架副本>/desk/开始搭建工作流.md` 原文、从头照做;之后凡读框架文件,一律读这份本地副本,不再上网读。

## 先守这几条

- 新项目按对接第 2 步判档选[满血预设](预设/满血.md)、[中型预设](预设/中型.md)或[小型预设](预设/小型.md),用户可当场改档;只装流程沿用现有选择,未选时按同一判法。去掉的文本地址与加回方式见所选预设的「去掉的文本在哪」段。
- 无论提示词,新项目先走首次需求对接;点头前除 `需求/` 外不建文件,第 0 步只往系统临时目录写;丙岔先完成第 2 步三项确认才建文件。
- 甲岔只在需求对接窗与第 20 步问用户;丙岔只在第 2 步和第 20 步问用户。三项缺哪项只追问哪项;其余拿不准的,一律按下文「占位符对照表」「别的默认值」及[附录「【填写】怎么填」](../docs/开始搭建工作流_附录.md#填写怎么填)三张表填,不追问。
- 每步先读那一句人话,再跑那一条命令,看完输出再走下一步。命令报错就停下,把报错原话告诉用户;同一条被拦两次不换第三种写法硬闯。
- 命令里的尖括号都是你要换成实值的字段,别的一个字不改:`<框架副本>` 由第 0 步打出;`<项目根>` 由第 1 步打出;`<章程目录>` 就是 `<项目根>/_office`;`<项目名>` 是第 1 问的答案;`<代码仓名>` 与 `<代码仓路径>` 由第 3 步打出;`<所勾位名>` 是用户勾的总监位名用英文逗号连起来(不含总编,例如 `后端,前端`);`<所勾各位目录>` 是同样这几个位名用空格隔开;`<位名>` 与 `<主题>` 是第 21 步定的需求件所在那一位和需求件的短主题。路径一律写正斜杠。
- 除第 4 步用 `mv` 搬需求产出外,命令只用 git 与 Python 3 标准库,Claude Code 与 GPT/codex 窗都照原样跑;有 `python` 用 `python`,没有时把命令开头的 `python -X utf8`(或裸 `python`)换成 `py -X utf8`,其余参数不变。
- 平台说明:Windows + Git Bash 验证过;Linux 写法已兼容、未实跑;Mac 未验证。
- 引用宪法、角色、模板、记忆规范处,一律读 `<框架副本>/desk/` 里的现文;已搬进 skill 的模板与规范节,按原处链接件去读 `<框架副本>/.agents/skills/` 下的现文;本向导只给路径,不抄它们的内容。
- 跟用户说话一律中文通俗话,不把命令递给他跑(第 18 步的退路除外)。

## 第 0 页 · 你是哪种情况

甲岔按三级找产品文档:① 用户给的或 `需求/` 下的产品文档 / 需求包(任何格式)直接用,不再推荐核对。② 没有则扫描工作目录含子目录,找名称或内容像产品、需求、研发、PRD、SRS、原型的 md、html、docx、pdf、txt 或图片,找到后问用户「按它来?开窗目录内的会挪进 `需求/`」;用户确认后采用。③ 仍没有则简单问三句:做什么、给谁用、第一版要有什么;提一句可选 `desk/先核对产品需求.md`(任意窗可跑),不在本窗走整套核对。

- **甲 · 新项目**:先走下节首次需求对接窗,成立后走「建仓与起台」。
- **乙 · 接管老项目**:转到[老项目接入向导](老项目接入向导.md),这里不重复写。
- **丙 · 只装流程**到现有仓:从第 0 步走建仓与起台,跳过首次需求对接窗与第 12 步(已有 git),其余按各步丙岔说明取值或跳过;第 1 步核现有仓根,不要求为空;第 2 步仍问项目叫什么 / 用一句话说它做什么 / 要激活哪几位总监;第 4 步 `需求/` 搬入不做。

## 首次需求对接窗

总编窗兼策划,开在 `{{开窗目录}}`,第一句自报「本窗是首次需求对接窗」。先做建仓第 0 步取框架副本,对接产出只落 `需求/`。

- **对接第 1 步 · 收需求**:用第 0 页找到的文档或三句回答。采用的文档若在开窗目录内且不在 `需求/` 中,按原格式挪进 `需求/`;只装材料的子目录整个挪成 `需求/<原目录名>/`。开窗目录外的才复制进 `需求/`;将文档来源或回答逐字记入 `需求原话_<日期>.md`。
- **对接第 2 步 · 判档与裁剪**:AI 从文档或回答直接归纳 `desk/真源/开局向导.md` ② 十题,从 `desk/真源/档案/` 拷最近的需求卡到 `需求/需求卡.toml` 填值,明写 `[规模] 档`,不逐题问。预计代码 ≤ 20 万行定中档、选中型预设;> 20 万行定大档、建议满血预设与按模块加总监;小型一窗到底只在用户点名时用。用户可当场改档。
  - d. 以 `desk/真源/` 为包根裁出 `需求/待确认/`,保留规模与特征、留下、拆掉与加回时机、自主假设和建议;命令见[附录](../docs/开始搭建工作流_附录.md#对接第-2-步)。
  - e. 判档依据与需求卡路径记入需求原话件末尾,卡每挪一处同步改路径。用户点名小型一窗到底时,点头后不建 `_office`、不装 `core/`;将裁出件、需求卡、`本项目自定.md`(如有)与三行 `CLAUDE.md` / `AGENTS.md` 照通用包 ⑥ 落项目根,收尾提示以后可走丙岔只装流程。
  - f. 中 / 大在建仓第 4 步搬入 `需求/` 后,把 `作业规矩.md`、`做法建议.md`、`拆掉清单.md`、`裁剪记录.json`、`开窗必读.md`(有才有 `当日口径.md`)、需求卡、`本项目自定.md` 同法挪到 `{{办公目录}}/` 根并同步原话件中的卡路径;裁出的 `宪法.md` 不落,落下的 `开窗必读.md` 里「宪法.md」改指 `desk/宪法.md`。减法提议照 `desk/模板/减法提议.md`,中型以上可选。
- **问岗位**:默认「总编 + 技术总监」:总编规划,技术总监一位包全部技术,主窗直派子代理、自并、自派独立审计;总监位名填「技术总监」,用户可改。≤ 20 万行一律此模式,> 20 万行才建议按模块加位。
- **对接第 5 步 · 拆解与规范**:依据产品文档按垂直功能切片拆单,每单从数据、逻辑、界面到测试能独立交付;落 `需求/拆解清单.md`(单名 / 模块 / 档 / 依赖 / 验收一句)。填框架副本的 `desk/模板/代码规范.md` 到 `需求/代码规范.md`,有美术 / 二进制素材才填 `需求/素材管理.md`。

把十题、需求卡、档与依据、裁剪及减哪些闸、预设、岗位、工期合成一次「判定报告」给用户点头,不逐题问。工期按「AI 工时,人类工时 ÷ 15」计算(例:150 天 → 10 天)。问「现在建仓还是先停」,用户说建才进建仓与起台;若点名小型则按上面 e 收尾。本窗不自己开别的窗。

把框架整仓 clone 到系统临时目录(不放进当前目录),打出的路径就是 `<框架副本>`;连不上 GitHub、没有 git 或 Python 3,就把报错原话告诉用户并停下。

命令见[附录](../docs/开始搭建工作流_附录.md#第-0-步)。

### 第 1 步 · 核当前目录

当前目录就是 `<项目根>`(即 `{{开窗目录}}`):甲岔除 .claude/ 与 需求/ 外为空、不在任何 git 仓里、路径不含空格,任一条不满足就停下,请用户换空目录重开窗。丙岔改为核现有仓根,不要求为空,但须在分支上、暂存区与工作区干净,路径仍不含空格;后续 `<代码仓路径>` 就是这个现有仓根,不另嵌套代码仓。

命令见[附录](../docs/开始搭建工作流_附录.md#第-2-步)。

### 第 3 步 · 算取值

把三问答案与下文三张表算成 `<项目根>/_work/开局/取值.json`,打出来逐行核。命令末参 `<岔>` 填 `甲` 或 `丙`:`<代码仓路径>` 甲取 `<项目根>/<代码仓名>`,丙取第 1 步核过的现有仓根(即 `<项目根>`);后续所有同名参数与占位都用此值,不再拼接仓名。

### 第 4 步 · 建办公仓

建 `<章程目录>`(即 `{{办公目录}}`),它是独立 git 仓、主支叫 main(摆法见 `<框架副本>/desk/架构.md`「一张图」与「`_office` 独立 git 仓规矩」两节)。甲岔随后将 `{{开窗目录}}/需求/` 用 `mv` 搬到 `{{办公目录}}/需求/`;代码规范、素材管理进办公目录根,按实存路径 `git add`。开窗目录不是 git 仓,不用 `git mv`;丙岔不做搬入。

附录第一块两岔都运行;第二块仅甲岔依次运行,没有素材管理件时跳过对应一行与登记项。

命令见[附录](../docs/开始搭建工作流_附录.md#第-4-步)。

### 第 5 步 · 写容器级权限

甲岔无现件时,把 `<框架副本>/desk/架构.md` settings 节首块权限写到 `<项目根>/.claude/settings.json`。丙岔及甲岔已有件时先读原配置:递归补缺键、列表去重追加,保留已有 permissions、hooks、env 及其他项;同键标量不同、类型不合或 JSON 无效就停报冲突,原件不动。末参 `<岔>` 沿用第 3 步;第 7a 步再合并框架 hooks。GPT/codex 窗也照写;办公窗经联接共用。

命令见[附录](../docs/开始搭建工作流_附录.md#第-5-步)。

### 第 6 步 · 摆框架文档

把 `<框架副本>/desk/` 整个复制成 `<章程目录>/desk/`(本向导除外):本项目里凡写 `desk/` 的路径都指这里,填好的宪法就是 `<章程目录>/desk/宪法.md`,记忆规范落在 `<章程目录>/desk/memory/`;其中 §1~§4、§6 已搬进 skill `memory-writing` 的 `references/`,§7 与三份换窗模板已搬进 skill `window-handoff-drafting` 的 `references/`,`desk/memory/` 原处只留链接,第 12a 步把 skill 拷进代码仓后正文在 `<代码仓路径>/.agents/skills/<skill 名>/references/`(换窗件本身按 `window-handoff-drafting` 的 `references/window-handoff-spec.md` 7.3 写进各位格子)。

命令见[附录](../docs/开始搭建工作流_附录.md#第-6-步)。

### 第 7 步 · 立章程

照 `<框架副本>/desk/角色/总编.md` 与 `模块总监.md` 开头「怎么用」①②,从「▼▼▼ 以下复制 ▼▼▼」下一行起切出章程,立总编与所勾各位的章程,各位格子里建好 `需求件/ 任务书/ 回执/ 资料/` 四格。

命令见[附录](../docs/开始搭建工作流_附录.md#第-7-步)。

### 第 7a 步 · 定开窗目录,把权限与 skill 联到办公目录

本步合装五类子代理、codex 并发、钩子与 CLAUDE.md、权限与 skill 联接:

- 子代理:Claude 平台把框架 `desk/子代理/` 五份拷进项目 `.claude/agents/`;codex / zcode 无此目录,派遣提示词首段逐字贴定义正文。派单只写顶级 / 困难 / 日常 / 轻量,模型对照见 `desk/模型对照表.md`。
- codex 并发:读 `~/.codex/config.toml` 的 `[agents] max_concurrent_threads_per_session`;缺键或 < 20,先备份到同目录 `config.toml.bak_<日期>` 再改成 20,一句话告诉用户;≥ 20 不动。
- 钩子与 CLAUDE.md:第 11 步填好办公目录后,照 `desk/架构.md` settings 节把 hooks 两条合并进 `<项目根>/.claude/settings.json`,不覆盖 permissions 与其他 hooks;两道 command 用架构的 `启动钩子.sh` 兜底:有 python 用它,否则用 `py -X utf8 -I`;`<产品目录>` 换成长留的 `<代码仓路径>`,不指临时目录,保留 `Write|Edit|MultiEdit` / 5 秒、`compact` / 10 秒。本步先按附录登记两处 `CLAUDE.md` 原貌,再把框架件装到 `<项目根>` 与 `<章程目录>`,填各自开窗路径并保留 `@AGENTS.md` 与三保留段。新建件全文核残留;已有件原字节不动,只在末尾补缺段,第 9 步只核追加段;同名段冲突停报,不得重登记掩盖旧文改动。
- 开窗层次见 `desk/架构.md`:总编及「带全记忆不干活」分身在 `<项目根>`(`{{容器路径}}`);总监、0 号、其余档员工与平台位在 `<章程目录>`(`{{办公目录}}`)根,不分位、不建子目录;甲岔代码仓与所有工作树不开窗;丙岔代码仓根兼项目根,可开总编窗。窗本体不 cd 进工作树,以免子代理继承目录自动读 AGENTS.md;仓命令用 `git -C <路径>`,build / test 用绝对路径或交子代理。办公仓窗不切分支、不建工作树、不碰分支切换器,提交只逐路径 add。Claude Code 按开窗目录分记忆:总编用项目根那份,办公目录各窗共用一份,只放跨位规矩,位内进章程;不建、不继承工位记忆,接棒只走交接件。
- 权限与 skill 真源只在项目根的 `.claude`、`.agents`;办公目录必须建同名整目录联接,否则发现不了项目根的 skill。命令①先建 `.agents` 目标再联接,Windows 经 Python 调 `mklink /J`,Linux/mac 用 `os.symlink`。办公窗由此读第 5 步 settings.json 与第 12a 步建好的 skills,「总是允许」写的 settings.local.json 也回项目根 `.claude`;codex 权限仍按启动参数与用户级配置,只经 `.agents` 发现 skill。首次开办公窗须信任目录,未信任(含无头模式)时 settings.json 放行与默认模式不生效。
- 命令②在办公仓 `.gitignore` 加 `.claude`、`.agents`(无斜杠),逐路径 add,第 25 步提交。命令③核 settings.json 与联接:甲岔 `.agents` 此时空,丙岔可有原内容;两岔 `.claude` 都含 settings.json。办公仓暂存项:甲岔 `.gitignore`、`需求/` 下各文件、`代码规范.md` 均标 `A`,有 `素材管理.md` 时也标 `A`;丙岔仅 `.gitignore` 标 `A`。已生成的 desk、章程、CLAUDE.md 可显示 `??`,两岔均不得有 `.claude` / `.agents` 行。乙岔已转老项目接入向导,不走本步。删联接见附录第 12a 步,禁递归删除。

命令见[附录](../docs/开始搭建工作流_附录.md#第-7a-步)。

### 第 8 步 · 建裁定簿与项目章程

宪法要引用的两份总账先建出来:裁定簿登第一条「宪法 v1.0 生效」,项目章程只放一张空的闸开关表(用法见 `<框架副本>/desk/宪法.md` 0.3)。对接第 2 步 f 落过 `开窗必读.md` 的(大 / 中),命令跑完后用改文件工具在项目章程加一行「作业层入口:`{{办公目录}}/开窗必读.md`(作业规矩 / 做法建议 / 拆掉清单)」,总监按需查,不作第四样必读。

命令见[附录](../docs/开始搭建工作流_附录.md#第-8-步)。

### 第 9 步 · 换占位符

仅替换第 6、7、8 步登记到 `<项目根>/_work/开局/生成件.json` 的本次新建 md(占位符表、填章程亲测页不换);不扫整仓,不碰需求原话、现有文档或 skill。登记件路径含联接就先停报,不穿过去写。`desk/模板/`、`desk/子代理/`、`desk/模型对照表.md` 的未知占位单列「模板留待填」,已定值仍换净;7a 安装副本也是模板源,不登记、不沿联接扫描,派遣前按模型对照表填值。正式生成件「还剩双花括号的」须为「无」;另必核 7a 两处开窗件,新件全文或旧件追加段有残留均点名并非零退出,不替换旧文。各步产物的核验边界见附录清单。

命令见[附录](../docs/开始搭建工作流_附录.md#第-9-步)。

### 第 10 步 · 带工单台进代码仓

甲岔向 `<代码仓路径>` 带入框架 `core/` 与忽略规则。丙岔向现有仓根带入 `core/`,保留原 `.gitignore` 并补框架、凭据与不入仓规则,另忽略 `_office/`、`_work/`、`_remote/` 和前序新建的 `.claude/` 配置。已有 `core/` 则停报冲突,不覆盖;工单台数据落 `core/data/`,不入仓。

### 第 12a 步 · 按平台建 skill 联接

## 收尾

最后一段回话用中文通俗话,依次写:

1. 一句话:项目搭好了,在 `<项目根>`。
2. 工单台网址(第 18 步打出的),说明浏览器打开就能看到各位与单;电脑重启后网页台会停,跟总编窗说一句「把网页工单台起起来」就行。
3. 第 27 步的默认值表原样贴上,紧跟一句「这些是我按默认填的,要改随时跟总编窗说」。
4. 第 28 步打出的激活句原样贴上,每句前写是哪一位。
5. 下一步:在 `<章程目录>` 里新开一扇窗(总监窗开在这里,不开在本窗所在的 `<项目根>`),贴需求-001 所在那一位的激活句;它报完本窗平台与可开的模型后照模型对照表直接派,要改模型跟它说一声;以后那扇窗还开着、要它看新件时,只贴四个字「查收工单」。有新需求就开总编窗。

系统临时目录里的框架副本留着不用管。说完即收尾,不再追问。
