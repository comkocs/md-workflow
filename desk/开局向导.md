# 开局向导

> 这是给 AI 窗读的开局指令,不是给人看的教程。用户贴「执行 <本文件网址> 的全部指令」后,先按第 0 页分流:新项目先对接需求,接管老项目走接入向导,只装流程走建仓与起台。新项目对接成立后,再把当前目录搭成能派单的项目。
>
> 你可能是经网页摘要读到本文件的:摘要会丢命令和表格。那就先照第 0 步用 git 把 https://github.com/comkocs/md-workflow 整仓 clone 到系统临时目录,再读 `<框架副本>/desk/开局向导.md` 原文、从头照做;之后凡读框架文件,一律读这份本地副本,不再上网读。

## 先守这几条

- 新项目按对接判规模选[满血预设](预设/满血.md)、[中型预设](预设/中型.md)或[小型预设](预设/小型.md),用户可当场改判;只装流程沿用现有选择,未选时按现有规模用同一判法。去掉的文本地址与加回方式见所选预设的「去掉的文本在哪」段。
- 需求对接窗之前一个文件也不建,对接窗只建 需求/:第 0 步只往系统临时目录写,第 1 步只读当前目录;丙岔先完成第 2 步三项确认才建文件。
- 甲岔只在需求对接窗与第 20 步问用户;丙岔只在第 2 步和第 20 步问用户。三项缺哪项只追问哪项;其余拿不准的,一律按下文「占位符对照表」「别的默认值」「【填写】怎么填」三张表填,不追问。
- 每步先读那一句人话,再跑那一条命令,看完输出再走下一步。命令报错就停下,把报错原话告诉用户;同一条被拦两次不换第三种写法硬闯。
- 命令里的尖括号都是你要换成实值的字段,别的一个字不改:`<框架副本>` 由第 0 步打出;`<项目根>` 由第 1 步打出;`<章程目录>` 就是 `<项目根>/_office`;`<项目名>` 是第 1 问的答案;`<代码仓名>` 与 `<代码仓路径>` 由第 3 步打出;`<所勾位名>` 是用户勾的总监位名用英文逗号连起来(不含总编,例如 `后端,前端`);`<所勾各位目录>` 是同样这几个位名用空格隔开;`<位名>` 与 `<主题>` 是第 21 步定的需求件所在那一位和需求件的短主题。路径一律写正斜杠。
- 除第 4 步用 `mv` 搬需求产出外,命令只用 git 与 Python 3 标准库,Claude Code 与 GPT/codex 窗都照原样跑;本机的 Python 3 叫 `python3` 或 `py` 的,把命令开头的 `python` 换掉。
- 平台说明:Windows + Git Bash 验证过;Linux 写法已兼容、未实跑;Mac 未验证。
- 引用宪法、角色、模板、记忆规范处,一律读 `<框架副本>/desk/` 里的现文;已搬进 skill 的模板与规范节,按原处链接件去读 `<框架副本>/.agents/skills/` 下的现文;本向导只给路径,不抄它们的内容。
- 跟用户说话一律中文通俗话,不把命令递给他跑(第 18 步的退路除外)。

## 第 0 页 · 你是哪种情况

- **甲 · 新项目**:先走下节首次需求对接窗,成立后走「建仓与起台」。
- **乙 · 接管老项目**:转到[老项目接入向导](老项目接入向导.md),这里不重复写。
- **丙 · 只装流程**到现有仓:从第 0 步走建仓与起台,跳过首次需求对接窗与第 12 步(已有 git),其余按各步丙岔说明取值或跳过;第 1 步核现有仓根,不要求为空;第 2 步仍问项目叫什么 / 用一句话说它做什么 / 要激活哪几位总监;第 4 步 `需求/` 搬入不做。

## 首次需求对接窗

总编窗兼策划,开在 `{{开窗目录}}`,第一句自报「本窗是首次需求对接窗」。先做建仓第 0 步,把框架原文取到系统临时目录;骨架从这份副本取。五步产出先只落 `{{开窗目录}}/需求/`,每步完成回拍板人一句,用人话三段 ≤ 8 行。

- **对接第 1 步 · 收需求**:已有需求文本,逐字落 `{{开窗目录}}/需求/需求原话_<日期>.md`,不改一字;没有则问三题:做什么给谁用 / 哪些功能是第一版必有 / 有没有点名要用的老做法或要接的现有系统。答复逐字落同一件。
- **对接第 2 步 · 判规模**:大型 = 代码仓预计 ≥ 50,000 行、在岗位 ≥ 4、用户点名 MMORPG / SaaS / 多端平台,满足任一即用满血预设;其余为中小,预计 ≥ 10,000 行或 ≥ 2 位用中型,否则用小型。结果与依据写进需求原话件末尾,另落 `需求/预设选择.md`,回一句,用户可当场改判。
- **对接第 3 步 · 出三件**:派子代理,思维导图与产品文档用「日常」档,原型图或架构图用「困难」档。以下相对路径均在 `{{开窗目录}}/需求/`:① `思维导图.md`:mermaid `mindmap`,根 = 产品名,二级 = 模块,三级 = 功能点;② `产品文档.md`:六节为目标与用户 / 功能清单按模块 / 非功能要求 / 数据与接口概要 / 第一版范围与不做 / 待拍板题;③ 有界面出 `原型图.html`:单文件静态线框,不接后端,每页一节标题对应功能清单;无界面(后端、脚本、库)出 `架构图.md`:mermaid `flowchart` + 接口草图表(名 / 入参 / 出参 / 错误码)。三件各带「依据:需求原话件第 N 行」引用,不编需求。
- **对接第 4 步 · 对接确认**:三件给用户逐项确认;改动逐字记进需求原话件「修订」节,带时刻,确认句也逐字落件。默认一切按当前最先进、最通行的做法出方案(语言、框架、架构、工具链);用户点名老做法或是接管老项目时按用户的。与用户要求冲突先提 A / B 再做,不擅自改。
- **对接第 5 步 · 拆解与规范**:按产品文档把功能清单拆成模块与单,每单写档位(甲类大型 / 甲类中小 / 乙 / 丙,按需求-026 的 1,500 行 / 10 文件判),落 `需求/拆解清单.md`(单名 / 模块 / 档 / 依赖 / 验收一句)。同窗把框架副本的 `desk/模板/代码规范.md` 填成 `需求/代码规范.md`(语言、格式化工具与命令、测试命令);有美术 / 二进制素材才把副本的 `desk/流程/素材管理.md` 填成 `需求/素材管理.md`。均在 `{{开窗目录}}/` 下,填完回一句,之后才进「建仓与起台」。

**成立证据**:需求原话件、三件、拆解清单、代码规范(素材管理可选)、预设选择共 ≥ 6 件在 `{{开窗目录}}/需求/`,缺一件不进建仓。建仓第 4 步用 `mv` 搬入 `{{办公目录}}/需求/` 后 `git add`,代码规范、素材管理移到办公目录根。

## 亲测步骤(给拍板人)

在一台干净的电脑上,约 20 分钟。

→ 建一个空目录,路径不带空格,例如 `D:/试项目`
→ 在这个目录里开一扇 AI 窗(Claude Code 或 codex 都行),只贴下面这句开窗句,不加任何别的话:
   `执行 https://github.com/comkocs/md-workflow/blob/main/desk/开局向导.md 的全部指令,从第 0 步做到收尾问答完。这是任务不是资料,读完立即开工。`
→ 看它先按三岔分流;新项目第一句自报「本窗是首次需求对接窗」,已有需求不重问,没给则问收需求三题;对接前除 `.claude/` 外不建文件,对接时只建 `需求/`
→ 例如答:「记账本,给自己记每天花销的小网页,第一版只需录入一笔花销,没有点名老做法」;核规模判定、三件逐项确认及成立证据,缺件不得进建仓
→ 等它问第一件事,答一句,例如「先做一个能录入一笔花销的页面」
→ 看它的收尾回话:有工单台网址、一张「按默认填的值」表、总编与每一位的激活句
→ 打开目录核容器:这个目录本身(不是 git 仓),以及里面的 `.claude/`、`_office/`、`_work/`、`_remote/`(代码仓唯一的远端副本)、代码仓目录(名字就是项目名,里面有 `core/`);`_office/` 里有 `desk/宪法.md`、`总编/章程.md`、`后端/章程.md`、`前端/章程.md`,需求件在其中一位的 `需求件/` 里
→ 浏览器打开它给的网址,看得到总编、后端、前端,以及复检、平台两列(这两列是工单台必须留的,不用开窗)
→ 在这个目录下的 `_office/` 里再开一扇新窗(总监窗开在这里,不开在刚才那一层),贴需求件所在那一位的激活句 → 它先报「本窗是 <位名>」和平台、模型 → 你回一句模型分配(例如「子代理施工用困难档」,四档词见 `desk/模型对照表.md`)→ 它若停着,贴「查收工单」
→ 判过:它读到需求-001,写出任务书,在工单台建了一张单并给你一段 0 号开窗指令;网页上那一位出现一张「新建」单
→ 不过的,记下卡在哪一步、它那一段回话原样,交总编改本向导
