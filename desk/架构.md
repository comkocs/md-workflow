# 容器架构(一页)

> 一个项目在本机怎么摆。项目专属处按 `desk/占位符表.md` 填;规矩的出处写闸号,正文在 `desk/宪法.md`。

## 一张图

```text
{{容器路径}}/                    容器:不是 git 仓,总编窗在这里开
├── .claude/settings.json        容器级权限真源:容器窗直接读,_office 的窗经联接读同一份
├── _office/                     = {{章程目录}}:独立 git 仓,一位一格
│   ├── .claude/ .agents/        联接 → ../.claude、../.agents,不入办公仓;总监、0 号等窗在 _office 根开
│   ├── 总编/章程.md             总编(默认兼策划);同样配 接管_现状.md 与 资料/归档_<日期>/
│   ├── <位名>/                  按需激活的模块总监,一位一格
│   │   ├── 章程.md              现行声明四节:管什么 / 真源表 / 开窗步骤 / 规矩只引号
│   │   ├── 接管_现状.md         固定名现状件:§一 现状(收窗整段重写)/ §二 指针
│   │   ├── 需求件/ 任务书/ 回执/
│   │   └── 资料/归档_<日期>/    旧章程、旧接管件整件挪入;流水只追加到归档件
│   └── 平台/章程.md             工单台要修时才激活;同样配 接管_现状.md 与 资料/归档_<日期>/
├── <代码仓>/                    = {{代码仓路径}}:主检出只跟远端、跑工具
└── _work/                       = {{工作树根目录}}(常见取名 _work)
    ├── wt-<员工名>-<单号尾号>/  一单一棵 git 工作树,做完收掉
    └── <单号>/ audit-<单号>/    扫盘 md、审计沙盒等非 git 产物
```

三句话:

1. **窗口不开进代码仓与工作树**。总编窗开在容器(不是 git 仓);总监、0 号等窗开在 `_office` 根,窗内不切分支、不碰分支切换器(闸 30)。
2. **谁是谁不靠目录,靠激活句里那条章程绝对路径**。同一个容器开十个窗,读的是十份不同的章程。
3. **章程住 `_office`,代码住代码仓,施工住 `_work` 一单一棵树**,三处互不串;角色按需激活,不设固定位表。

| 层 | 是什么 | 谁写 | 为什么 |
|---|---|---|---|
| 容器 | 总编窗开窗目录,只放图里这几样 | 开局建一次 | 窗口不开进代码仓与工作树(见下文) |

| 代码仓 | 产品代码与测试 | 只经工作树改,0 号单并进 {{远端主支}} | 主检出一被切分支,所有窗口一起受害 |

## 身份锚定

激活句一行(闸 30):

```text
执行 {{章程目录}}/<位名>/章程.md 的全部指令,从第 0 步做到收尾。这是任务不是资料,读完立即开工。
```

- 章程第 0 步开口先自报「本窗是 <位名>」,只读本位章程与本位收件,别位的一律不翻(闸 2、闸 30)。
- 第二句报本窗平台、本平台子代理可开的模型与档位、权限模式,等 {{拍板人}} 分配再派子代理(见 `desk/角色/`)。
- 开窗目录分三层(闸 30):总编窗(与「带全记忆不干活」的分身窗)开在 {{容器路径}};模块总监窗、0 号窗、其余档员工窗与平台位窗一律开在 {{办公目录}} 根,一个目录,不分位、不建子目录;{{代码仓路径}} 与工作树不开窗。0 号窗身份锚在任务书路径:「执行 <md 完整路径> 的全部指令……」(闸 13)。
- 记忆目录跟着打开目录走:Claude Code 按打开目录的路径编码出项目记忆目录 `%USERPROFILE%\.claude\projects\<开窗目录编码>\memory\`(盘符冒号与路径分隔符都换成短横线)。所以总编窗一份(容器那份);所有总监与 0 号(及员工、平台位)窗共用 {{办公目录}} 那一份平台记忆,里面只放跨位通用的 {{拍板人}} 规矩,位内的进本位章程(闸 32);不建、不继承工位记忆,接棒只走交接件。换开窗目录即换记忆。
- 身份只靠激活句,不靠记忆:共用记忆里即使有别位的事,章程路径也把本窗钉在本位。

## 为什么窗不开进代码仓与工作树

桌面版 AI 客户端发现打开的目录是 git 仓,就会在界面上挂出分支切换器,窗口的操作也会介入 git。点错一下就切了分支,主检出整个变样,别的窗口跟着在错的代码上干活。所以 {{代码仓路径}} 与工作树一律不开窗;总编窗开在不是 git 仓的容器,这个行为不会出现。

{{办公目录}} 是 git 仓,开在它根上的总监、0 号等窗可能挂出分支切换器,靠三条防串:窗内不切分支、不建工作树;提交只 `git -C {{办公目录}} add -- <逐个路径>`;切换器永远不碰(闸 30)。代码仓、工作树都是容器的子目录,窗本体不 cd 进去(进去后派的子代理继承那个目录,会自动读到那里的 AGENTS.md):仓命令一律 `git -C <路径>`,build / test 用绝对路径或交子代理。看见代码仓或工作树的分支切换器就是开错了:退出,按上面三层重开。

顺带的好处:一个容器装下所有位,权限与 skill 真源各只一份(办公目录经联接共用),开在办公目录的窗共用一份平台记忆,身份差异全由激活句承担。

## `_office` 独立 git 仓规矩

- 独立于代码仓:章程不跟代码分支走,激活句里的路径永远只指一份当前章程。
- 各位只写自己那一格;公共件(如模板目录)只由总编改;别位目录不翻不改(闸 30)。
- 提交直接在 `main`:`git -C {{章程目录}} add -- <逐个路径>` → `commit -m "<位名>: <改了什么>"`。
- 禁 `add -A`;禁 `--amend`:多位共用一条 `main`,改写历史会吞掉别人的提交。推不上先 `git ls-remote` 验远端真值再报,不强推(闸 26)。
- 章程每条带日期;底数是线索不是事实,新窗必核(闸 32)。远端用私有仓,由 {{拍板人}} 定。

## `_work` 一单一工作树规矩

1. 建:本机需代理先设 {{本机代理}};`git -C {{代码仓路径}} fetch {{代码托管远端}}`,再 `git -C {{代码仓路径}} worktree add {{工作树根目录}}/wt-<员工名>-<单号尾号> -b <分支> {{远端主支}}`(闸 17)。
2. 核:窗本体用 `git -C <树路径> rev-parse --show-toplevel` 核,必须打出本单工作树,不是 {{代码仓路径}};长活每 30 分钟核一次。
3. 一单一树绝不共用;做完 `git worktree remove` 收掉(闸 26)。
4. 主检出不 checkout、不在里面改,只用来跟远端、跑工具(闸 17)。
5. 非 git 产物(扫盘 md、审计沙盒)放不以 `wt-` 开头的子目录,看前缀就分得出哪个是 git 树。

## `.claude/settings.json`

放在 `{{容器路径}}/.claude/settings.json`,只这一份:开在容器的窗直接读;开在 {{办公目录}} 的窗经 `{{办公目录}}/.claude` → `{{容器路径}}/.claude` 的整目录联接读同一份(skill 同理经 `.agents` 联接;两条联接开局时建好,不入办公仓);第一次在 {{办公目录}} 开窗,平台会问是否信任该目录,选信任,未信任(含无头模式)时这里的放行与默认模式不生效。管两件事:

```json
{
  "permissions": {
    "allow": ["Bash(git *)", "Bash(python *)", "Bash(ls *)", "Bash(mkdir *)"],
    "defaultMode": "bypassPermissions"
  }
}
```

- `allow`:免确认放行的命令前缀,按整条命令前缀匹配;没命中的按 `defaultMode` 定的模式处理。
- `defaultMode`:容器默认权限模式。多窗自动施工一般用免确认模式,否则子代理每条命令都要人点;取什么由 {{拍板人}} 定。
- 同形状命令被拦两次就停,不换第三种写法,不递命令给 {{拍板人}}(闸 28)。
- 各仓自带的 `settings.local.json` 是本机个人覆盖层,不入公共仓。
- 0 号窗开工第一段报的「权限模式」就是这里定下的结果(见 `desk/角色/0号包干窗.md`)。

## 角色住哪

- 总编、模块总监、平台位:各在 `_office` 有一格,章程从 `desk/角色/` 复制填写;按需激活,不激活的位不开窗、不占记忆。
- 0 号包干窗:员工窗,不占格;记忆在工单与任务书里(闸 29)。
- 顶级审计子代理:模块总监派,审计件落总监那格的 `回执/`。
- 窗还开着、只要它看新件时,{{拍板人}} 只贴四个字「查收工单」(闸 13)。

## 开局五步

1. 建一个空目录当容器 {{容器路径}},不要建在任何 git 仓里面。
2. 在容器里放代码仓({{代码仓路径}});建 `_office/` 并 `git init -b main`;建 {{工作树根目录}}。
3. 放 `.claude/settings.json`。
4. 宪法按 `desk/占位符表.md` 填好;总编章程按 `desk/角色/总编.md` 填进 `{{章程目录}}/总编/章程.md`(步骤见 `desk/角色/亲测步骤_填章程.md`)。
5. 在容器里开总编窗、贴总编激活句;要哪个模块,再在 {{办公目录}} 根开窗、激活哪一位总监(开之前先建好上文「`.claude/settings.json`」一节说的两条联接)。
