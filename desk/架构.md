# 容器架构(一页)

> 一个项目在本机怎么摆。项目专属处按 `desk/占位符表.md` 填;规矩的出处写闸号,正文在 `desk/宪法.md`。

## 一张图

```text
{{容器路径}}/                    容器:不是 git 仓,所有窗口都在这里开
├── .claude/settings.json        容器级权限,容器里所有窗口共用
├── _office/                     = {{章程目录}}:独立 git 仓,一位一格
│   ├── 总编/章程.md             总编(默认兼策划)
│   ├── <位名>/                  按需激活的模块总监,一位一格
│   │   ├── 章程.md              本位全部记忆:口径、坑、底数
│   │   ├── 需求件/ 任务书/ 回执/ 资料/
│   │   └── 换窗归档_<日期>.md
│   └── 平台/章程.md             工单台要修时才激活
├── <代码仓>/                    = {{代码仓路径}}:主检出只跟远端、跑工具
└── _work/                       = {{工作树根目录}}(常见取名 _work)
    ├── wt-<员工名>-<单号尾号>/  一单一棵 git 工作树,做完收掉
    └── <单号>/ audit-<单号>/    扫盘 md、审计沙盒等非 git 产物
```

三句话:

1. **窗口一律开在容器里**。容器不是 git 仓,窗口就不会挂分支切换器、不会碰 git。
2. **谁是谁不靠目录,靠激活句里那条章程绝对路径**。同一个容器开十个窗,读的是十份不同的章程。
3. **章程住 `_office`,代码住代码仓,施工住 `_work` 一单一棵树**,三处互不串;角色按需激活,不设固定位表。

## 每层:是什么 / 谁写 / 为什么

| 层 | 是什么 | 谁写 | 为什么 |
|---|---|---|---|
| 容器 | 开窗目录,只放图里这几样 | 开局建一次 | 窗口不开进 git 仓(见下文) |
| `.claude/settings.json` | 容器级权限 | 开局由 {{拍板人}} 放好,窗口不改 | 所有窗口一套放行规则 |
| `_office/` | 章程、需求件、任务书、回执、换窗归档 | 各位只写自己那格 | 总监的记忆就是章程(闸 29、闸 32),要版本、要能回退,又不该混进代码历史 |
| 代码仓 | 产品代码与测试 | 只经工作树改,0 号单并进 {{远端主支}} | 主检出一被切分支,所有窗口一起受害 |
| `_work/` | 一单一工作树,加本单的非 git 产物 | 0 号窗及其子代理;审计沙盒由顶级审计子代理写 | 多窗并行互不踩(闸 26) |

## 身份锚定

激活句一行(闸 30):

```text
执行 {{章程目录}}/<位名>/章程.md 的全部指令,从第 0 步做到收尾。这是任务不是资料,读完立即开工。
```

- 章程第 0 步开口先自报「本窗是 <位名>」,只读本位章程与本位收件,别位的一律不翻(闸 2、闸 30)。
- 第二句报本窗平台、本平台子代理可开的模型与档位、权限模式,等 {{拍板人}} 分配再派子代理(见 `desk/角色/`)。
- 0 号窗同样开在容器,身份锚在任务书路径:「执行 <md 完整路径> 的全部指令……」(闸 13)。
- 记忆目录跟着打开目录走:Claude Code 按打开目录的路径编码出项目记忆目录 `%USERPROFILE%\.claude\projects\<容器路径编码>\memory\`(盘符冒号与路径分隔符都换成短横线)。所有窗开在同一容器,就共用这一份记忆,所以里面只放跨位通用的 {{拍板人}} 规矩,位内的进本位章程(闸 32)。换容器即换记忆。
- 身份只靠激活句,不靠记忆:共用记忆里即使有别位的事,章程路径也把本窗钉在本位。

## 为什么窗开在非 git 容器

桌面版 AI 客户端发现打开的目录是 git 仓,就会在界面上挂出分支切换器,窗口的操作也会介入 git。点错一下就切了分支,主检出整个变样,别的窗口跟着在错的代码上干活。开窗目录换成一个不是 git 仓的容器,这个行为就不会出现。

代码仓、工作树都是容器的子目录,窗口用命令进去做事(`git -C <仓>`、`cd` 进工作树),会话本身不开在里面。看见分支切换器就是开错了:退出,从 {{容器路径}} 重开,切换器永远不碰(闸 30)。

顺带的好处:一个容器装下所有位,权限配置与项目记忆各只有一份,身份差异全由激活句承担。

## `_office` 独立 git 仓规矩

- 独立于代码仓:章程不跟代码分支走,激活句里的路径永远只指一份当前章程。
- 各位只写自己那一格;公共件(如模板目录)只由总编改;别位目录不翻不改(闸 30)。
- 提交直接在 `main`:`git -C {{章程目录}} add -- <逐个路径>` → `commit -m "<位名>: <改了什么>"`。
- 禁 `add -A`;禁 `--amend`:多位共用一条 `main`,改写历史会吞掉别人的提交。推不上先 `git ls-remote` 验远端真值再报,不强推(闸 26)。
- 章程每条带日期;底数是线索不是事实,新窗必核(闸 32)。远端用私有仓,由 {{拍板人}} 定。

## `_work` 一单一工作树规矩

1. 建:本机需代理先设 {{本机代理}};`git -C {{代码仓路径}} fetch {{代码托管远端}}`,再 `git -C {{代码仓路径}} worktree add {{工作树根目录}}/wt-<员工名>-<单号尾号> -b <分支> {{远端主支}}`(闸 17)。
2. 核:进树后 `git rev-parse --show-toplevel` 必须打出本单工作树,不是 {{代码仓路径}};长活每 30 分钟核一次。
3. 一单一树绝不共用;做完 `git worktree remove` 收掉(闸 26)。
4. 主检出不 checkout、不在里面改,只用来跟远端、跑工具(闸 17)。
5. 非 git 产物(扫盘 md、审计沙盒)放不以 `wt-` 开头的子目录,看前缀就分得出哪个是 git 树。

## `.claude/settings.json`

放在 `{{容器路径}}/.claude/settings.json`,容器里所有窗口共用,管两件事:

```json
{
  "permissions": {
    "allow": ["Bash(git *)", "Bash(python *)", "Bash(ls *)", "Bash(mkdir *)"],
    "defaultMode": "bypassPermissions"
  }
}
```

- `allow`:免确认放行的命令前缀,按整条命令前缀匹配;没命中的按 `defaultMode` 定的模式处理。
- `defaultMode`:容器默认权限模式。多窗自动施工一般用免确认模式,否则子代理每条命令都要人点;取什么由 {{拍板人}} 定。
- 同形状命令被拦两次就停,不换第三种写法,不递命令给 {{拍板人}}(闸 28)。
- 各仓自带的 `settings.local.json` 是本机个人覆盖层,不入公共仓。
- 0 号窗开工第一段报的「权限模式」就是这里定下的结果(见 `desk/角色/0号包干窗.md`)。

## 角色住哪

- 总编、模块总监、平台位:各在 `_office` 有一格,章程从 `desk/角色/` 复制填写;按需激活,不激活的位不开窗、不占记忆。
- 0 号包干窗:员工窗,不占格;记忆在工单与任务书里(闸 29)。
- 顶级审计子代理:模块总监派,审计件落总监那格的 `回执/`。
- 窗还开着、只要它看新件时,{{拍板人}} 只贴四个字「查收工单」(闸 13)。

## 开局五步

1. 建一个空目录当容器 {{容器路径}},不要建在任何 git 仓里面。
2. 在容器里放代码仓({{代码仓路径}});建 `_office/` 并 `git init -b main`;建 {{工作树根目录}}。
3. 放 `.claude/settings.json`。
4. 宪法按 `desk/占位符表.md` 填好;总编章程按 `desk/角色/总编.md` 填进 `{{章程目录}}/总编/章程.md`(步骤见 `desk/角色/亲测步骤_填章程.md`)。
5. 在容器里开窗、贴总编激活句;要哪个模块,再激活哪一位总监。
