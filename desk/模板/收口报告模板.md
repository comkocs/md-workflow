# 收口报告模板(0 号包干单、甲档、乙档共用)

## 规格

- 全文 ≤6,000 字,只留下面四块;四个二级标题逐字照写,不加序号、不改字。
- 字数按字符算,不按字节算。部分终端的 `wc -c`、`wc -m` 对中文都只数字节,会高估约一倍。量法(路径用参数传,不塞进 `-c` 字符串,中文路径塞进去在部分终端会被本地代码页误解码):

  ```
  python -X utf8 -c "import io,sys;print(len(io.open(sys.argv[1],encoding='utf-8').read()))" "<文件路径>"
  ```

- 由执行窗派子代理起草,执行窗只核:哈希用 git 核、数字用命令核、文件名用列目录核(闸 34)。
- 落 `{{章程目录}}/<位名>/回执/<单号>_收口报告.md`。
- 丙档不交收口报告,只回一行回执(闸 14)。
- 旧「收尾问答六项」不再单列:计划外改动并进事实段;「以后改这个数改哪个符号」并进自主假设;「留给下一窗的坑」取消。

## 不进收口报告的

- 红集逐名对账 → 审计件(`审计件模板.md`)。
- 跨窗协调 → 对话线小表 `单号 | 交集文件 | 谁先上 | 需要对方做什么`。
- 给总编的裁定簿({{裁定簿路径}})补登条文 → 单独成文件 `{{章程目录}}/<位名>/回执/<单号>_裁定簿补登.md`,占 0 号单产出 ≤4 件里可选的那 1 件。
- 流水账、过程复述。做不完的只写「事件还没发生 / 归别位」两类之一(闸 31),放进「需总监动作」。

## 骨架(下面整段抄走填空)

```
# <单号> 收口报告(<一句话标题>)

## 结论一行
<进度词,闸 20 六词之一> · 并线提交 <哈希;甲乙档写本支提交号> · 部署头 <哈希,或「无上服」> · 红集新增 <N>

## 事实段(≤600 字)
<做了什么;基点提交与组合树头;构建与全回归结果(通过数 / 失败数,连基点提交号);计划外改动(改了谁的文件、改了什么、为什么);{{拍板人}} 当窗拍板的出处(进度件第几段或对话线留言时刻),不抄原话全文。>

## 需总监动作
1. <3~5 条。每条一个动作:谁做、做什么、为什么;要别位做的写明是哪一位;做不完的写明属于「事件还没发生」还是「归别位」。>

## 收尾三问
1. 怎么打开它:<用户怎么打开它(内部单写 {{拍板人}} 怎么打开它),给得出命令或路径(闸 21)。>
2. 最没把握的一处:<只写一处:为什么没把握、怎么验能消除。>
3. 自主假设:<逐条:定了什么、为什么、写进了哪个文件哪个符号;自定的数标「这是自定,不是裁定」(闸 16)。>
```

## 每块写什么、不写什么

| 块 | 写 | 不写 |
|---|---|---|
| 结论一行 | 一行:进度词、并线提交(甲乙档写本支提交号)、部署头、红集新增数 | 「完成」「收官」这类没有对象的词(闸 20) |
| 事实段 | 可核的事实,每个数带出处 | 过程叙述、自我评价、测试逐名清单 |
| 需总监动作 | 要总监或别位接手的动作 | 本窗能做完却没做的活(闸 31:能做完的全部做完) |
| 收尾三问 | 三问各答,答不出写「无」并说为什么 | 与三问无关的补充说明 |
