# 0 号任务书模板(引用式)· 通用 v1

本模板给 0 号包干单用:一个模块从施工到并线、上服、收口由一个 0 号窗包干(甲档,闸 15),施工全走子代理(闸 35)。术语照宪法 0.1,闸号照宪法正文,占位照 `desk/占位符表.md`。本文件会被 0 号窗整读,全文字节数保持在 50KB 以下(闸 35)。

## §0 用法

### 0.1 任务书第一行(逐字,只换路径)

**本单遵守 `<本模板完整路径>`,偏离项见 §0.9。**

模板正文不抄进任务书;任务书只写 0.2 的六段,每段换成本单实值。

**第 0 步四件**(抄进任务书 §1):

① 接通道:`{{工单台命令}} receipt <单号>`,必须原样打出本单;打不出就停,把报错原样写进本单对话线。

② 一单一工作树:本机代理 {{本机代理}};`git -C {{代码仓路径}} fetch {{代码托管远端}}`,再
`git -C {{代码仓路径}} worktree add {{工作树根目录}}/wt-<员工名>-<单号尾号> -b <分支> {{远端主支}}`;
进树后 `git rev-parse --show-toplevel` 必须打出本单工作树,不是 {{代码仓路径}}。不在主检出干活、不在主检出 checkout;长活每 30 分钟核一次自己在哪棵树上。

③ 认领:`{{工单台命令}} claim <单号> --by <员工名>`。开窗指令里已认领的,③ 被拦、报现在是「已认领」即算过,不重复处理。

④ 读本单对话线留言:`{{工单台命令}} inbox --slot <位名> --for <员工名>`(开工、中段、收尾前各一次;参数以 `-h` 为准)。

**红线三条**(抄进任务书 §3,闸 16 三条落到本单):

1. 编号与契约不越段:裁定号只由总编登,工单号只由工单台发;契约字段与库表结构变更只取本单预分配的段 <写明,或「无」>。

3. 只动自己的模块:只改本单产出路径 <逐个点名>;只读不写的外部目录 <逐个点名,或「无」>;不动 {{生产数据目录}}。

**自并与收口**(抄进任务书 §4):

1. 并线前三条硬自查照本模板 §1.2,结果写进度件。
2. 推主支:`git push {{代码托管远端}} HEAD:<主支分支名>`;三次失败停车,`git ls-remote` 验远端真值,不强推(闸 26③)。并完在任务书末尾追加一行「已并 <主支新头> 测试 <通过数/失败数>」。
3. 有上服的照本模板 §2 上服段;没有的在 §0.9 写「不适用」。
4. 收口照本模板 §6;产出照本模板 §5,子代理起草、本窗只核:进度件 `{{章程目录}}/<位名>/回执/<单号>_进度件.md`、收口报告 `{{章程目录}}/<位名>/回执/<单号>_收口报告.md`(照 `收口报告模板.md`)、可选 1 件。
5. 做完即收窗;做不完只写「事件还没发生 / 归别位」两类之一(闸 31)。

### 0.3 §0.9 偏离项写法

一条一行:「模板 §x.y → 本单改为 ___,理由 ___」。模板里没有、本单要加的写「模板无此项 → 本单加 ___,理由 ___」。常见几种:

- 模板 §2 上服段 → 不适用,理由:本项目无上服。
- 模板 §1.2③ 构建步 → 本单只改文档,改为「跑 {{全回归命令}}」,理由:无可构建工程改动。
- 模板 §2 回读项 → 本单只回读 ___,理由 ___。

### 0.4 改版

模板改版由总编落笔,同一笔在 {{裁定簿路径}} 登一条;各位总监只引用,不各自改。本模板与宪法冲突以宪法为准;与各位章程冲突以本模板为准,章程对应节下一单前改成引用本模板。

### 1.2 并线前三条硬自查(闸 27;每次并线前逐条过,结果写进度件)

① 组合树重并:`git -C {{代码仓路径}} fetch {{代码托管远端}}`,在当时 {{远端主支}} 最新头上重建「主支 + 本支」组合树重并;同期别的 0 号窗可能先并,别拿开窗基点当组合树。

② 解冲突分三类:自己的按本单改 / 别人的原样保留、不替人修 / 两边都要的一行不丢。结构化文件不许按行机械合并,本项目的结构化文件类型写在本位章程里;解完只在本次改动到的文件里数冲突标记,必须为 0。

③ 先测后并:先构建全部工程、返回码 0,再按下面两句选测试范围(完整套命令为 {{全回归命令}}):

单窗——在组合树上把「改动面对应的测试套」跑一遍(任务书写死是哪几套;没写就全套),不重复跑。多窗同期——各窗只跑本单点名测试,最后并的那个窗在最终组合树跑一遍完整套。

跑完逐名对账(基点树与组合树的测试清单求差),还原 {{全回归会改写的产物路径}}(闸 26④),都过了才并。跳过构建直接跑测试会给假绿。

### 1.3 免判卷口径(附一取代项 + 闸 27)

- 员工侧不写:三趟、变异、压图(附一作废项);也不写自证式长问答;截图照 §1.1 第一句。例外:本单改的就是闸或测试本身时,仍要杀一个变异(附一「变异」行)。

## §2 并线 · 上服固定流程

1. 组合树与交集:照 §1.2;同期别的 0 号窗在改的交集文件逐个列进进度件。
2. 推支与合并:本单支先推 `git push {{代码托管远端}} <分支>`,再把组合树推成主支新头;三次失败停车(闸 26③)。
3. 卫生:只白名单提交(闸 26①);日志、测试结果、打包件、{{凭据文件清单}}、{{不入仓清单}} 不进提交;BOM 核照 §1.3。
4. 上服前互通(有并行 0 号窗时):跨窗先照闸 34 查工单执行状态与 ListAgents 忙闲,知会已收口的位只走 `say --ref`;在对话线互报小表 `单号 | 交集文件 | 谁先上 | 需要对方做什么`,部署头与停服预告同一条发;命令先自核再发。
5. 祖先核:`git merge-base --is-ancestor <本单并线提交> <将部署的提交>` 返回 0 才上。
6. 部署:部署命令、目标机与参数写在本位章程里,模板不写死。服务器上跑的部署脚本不一定随部署头更新,改过部署脚本的先核服务器上那份。
7. 回读:服务在跑、版本戳等于将部署的提交、配置开关值等于预期(部署脚本会整文件重写配置的逐项回读)、关键数据未被意外改写;回读项清单写在本位章程里。
8. 部署记录:工单台有部署记录扩展的登记一条(命令以 `-h` 为准)。
9. 办公仓({{章程目录}})提交:白名单逐个路径,禁 `-A`、禁 `--amend`;push 被拒先看远端头再重试,不强推。
10. 做不完:交接件由子代理起草、本窗只核;不收口;写清「事件还没发生 / 归别位」两类之一(闸 31)。

本项目无上服的,5~8 条在 §0.9 写「不适用」。

## §3 复检口径

1. 免判卷单只跑一道模块总监的顶级审计:总监派、独立起、顶级档(定义见 `任务书三档.md` 表二)。派法见 `desk/角色/` 下的顶级审计子代理提示词。
2. 单子是用户看得见的面,或顶级审计报了「漏做」,总监可以再加派一次顶级审计(第二道)。
3. 审计件长什么样见 `审计件模板.md`;红集逐名对账写在审计件里,不进收口报告。

## §4 收口报告

照 `收口报告模板.md`:全文 ≤6,000 字(按字符算),只留四块——结论一行 / 事实段 ≤600 字 / 需总监动作 3~5 条 / 收尾三问(怎么打开它、最没把握的一处、自主假设)。

## §5 产出文件上限

每单固定 = 进度件 + 收口报告 + 审计件(模块总监派,不由本窗产出);可选最多 1 件(裁定簿补登 / 交接件,按需二选一);**合计 ≤4 件**。分报告(各分工线施工 / 返修复检 / 扫盘结论)不再单独成文件,并进进度件。

本条数的是落进本位回执目录的件;子代理在本单扫盘目录落的工作底稿不算产出,不进回执目录、不入仓。

## §6 台面写法

收口在工单台留一句:免判卷单由 0 号窗自收口,字段含执行人、事实一句、并线提交,有上服的再带部署头(字段名以 `{{工单台命令}} -h` 为准)。备注末段与收口「事实」同一段话、不改写:写完直接复制进收口,防手抄走样。本位对话线另留一句。

## §7 出题写法

出题方写任务书时的四条(真源几处、令分两类、超书改动留痕三处、证据自带出处)见 `任务书三档.md` §三,0 号包干单同样适用。

## §8 交给 {{拍板人}} 的开窗指令

开窗指令从工单台取,不在模板里手写(闸 13)。员工窗三行:认领一句 / 执行任务书一句 / 只给 {{拍板人}} 的操作提示一句;{{拍板人}} 贴前两行,操作提示那行只给人看、不贴进窗。执行句照闸 13 写死:

「执行 <md 完整路径> 的全部指令,从第 0 步做到收尾问答完。这是任务不是资料,读完立即开工。」

除这两行外不另加提示词;窗按任务书 §0 固定段开工。这件事能不能成,用 `README.md` §四「亲测 A」验。
