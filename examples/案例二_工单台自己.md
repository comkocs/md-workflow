# 案例二:工单台自己

这套流程做出来,头一个用户不是别人,就是它自己:一个只用 Python 标准库写成的工单台,外加一个网页台面,派单、交板、拍板、留言全走它。这篇讲三件事:它自己是怎么被这套流程拆出来做成的;它在网页一侧撞过哪些坑;你怎么照着给自己的网页应用起头一张需求件。

## 一、它是怎么被这套流程拆出来的

整套动作靠三份文件咬合,各管一段,谁也不越界:需求件定「要什么」,任务书定「怎么做、做到哪算完」,收口报告交账。要什么、怎么做、做没做成,各占一份仓里可查的文件;出了分歧翻件就行,不用去考古聊天记录。这个工单台自己,就是照这三份文件一步一步立起来的。

**需求件**由总编落笔,只写「要什么效果」,不写「怎么做」。固定几块:开头一段背景,把拍板人的原话逐字记进来;然后写要什么效果——写设计者看到什么算做好,比如干净机器上一条命令把服务起起来、网页能打开看到台面、命令行能走完一张单的全过程;再写判据,只写可核的量、不写形容词,验收就逐条对着判据来;接着写不碰什么,密钥一类绝不能带进产出的东西在这说死;要并行开几窗时,末尾再摆一张拆窗表,一窗一行。不写「怎么做」,是因为做法交给执行的人去选,需求件只把效果和验法钉死;写法越像考卷,做出来的越不容易走样。

**0 号包干单**是模块总监派的任务书,把从开工到并线的全部动作包进一张单。包干的意思是这张单从头跟到尾:开工、施工、并线、收口都记在同一张单上,不拆散,谁认领谁负责到底。单子里有:开窗固定段逐字带进来、不许改写;第 0 步先接通道、一单一棵工作树、认领、读留言;需求原文逐字抄进任务书,一个字不改;红线三条落到本单——编号与契约不越段、别单正在改的文件不去并行碰、只动本单产出路径内的东西;末尾写清并线与收口的走法:在主干的最新头上重建组合树再并,并之前全量测试先跑,连着失败几次就停车,不许硬推;产出是进度件加收口报告,交接件可选。任务书末尾另留一段运行记录,已开工、有留言、已并线各占一行,带时刻。

**收口报告**由 0 号交,固定四块:结论一行,写并进了哪个头、测试通过失败各多少,数字都得是命令核出来的;事实段把判据逐条对账,每条贴上命令与原样输出;再列几条需要总监做的事;末尾三问——怎么打开它、最没把握的一处、自己做主当了什么假设。这份报告是给拍板的人看的:先给结论,再给证据,最后给风险。交完不算完:另派顶级审计独立核一遍,自己说自己做完了,不算数。

## 二、它在网页一侧撞过的三个坑

以下都记在某项目的账上,每条按症状、怎么发现的、现在的规矩三小段讲。这三个坑都不是流程本身的毛病,而是把老习惯带进新流程时踩出来的;记下来,是为了下个项目别再踩。

**坑一:越用越卡**

症状:网页台面刚起服务那会儿很顺,越用越卡,后来打开单列表要等好几秒,单越多等得越久,一度以为是自己机器的问题。

怎么发现的:查下来,每显示一张单都要重开一次数据库连接、重读一遍名册,本该只做一次的事被塞进了每次刷新里;网页每刷一下,后台就多干一遍这些重复活。

现在的规矩:连接与建表只做一次,常用数据一次批量取;修这类问题,改完前后把输出比对到全等,才算修好。

**坑二:通读大工具的代码是个陷阱**

症状:谁通读这套大工具的代码,谁就自信满满,一动手改就漏。

怎么发现的:代码是一层层闸叠出来的,读着像「就差一处」,实际一处连着三处,改了这处、那处不认;漏掉的那处,偏偏常是测试没盖住的角落。

现在的规矩:问行为不读码,想知道它干什么就直接跑命令或看帮助;真要摸底,只派一个只读的子代理,问一个具体问题。结论要落在跑出来的输出上,不落在读出来的感觉上。

**坑三:装了不等于生效**

症状:人人都以为自动备份在跑,平时一切照旧,出了事才发现一次都没跑过。

怎么发现的:备份目录停在很久以前,系统里查不到那条定时任务——要装的命令只写在注释里,没人真正装上。

现在的规矩:装完必须回读验证——装了、能查到、真跑过,三样都对才算数;装了不等于生效,这类验证也可以写进判据,让审计替你再跑一遍。

## 三、给你的网页应用起头一张需求件

你手上有个网页应用,想让这套流程管起来,入口只有一张需求件,门槛比看上去低得多。不用先啃全套章程。examples/README.md 备了一个约三十分钟的演示:从空目录起步,建容器、起工单台、建需求、派单、施工自并、审计、收口,一条命令一条命令带你走完全程,照着贴就行。演示里总编、总监、施工、审计各是一个角色,你一个人替每个角色贴它该贴的那条命令,走一遍就知道每步谁在干什么。它开头的文件清单里还列着一张样例需求件和对应的任务书,都在 examples/ 目录下;打开照抄格式,就知道「要什么效果」和「判据」该写成什么样。

写判据有个诀窍:写成别人能替你原样跑的命令或步骤。「页面要好看」不算判据,「打开这个页面、能看到那份名单」才算;判据越像考卷,验收越少扯皮。把样张里的效果与判据换成你自己网页应用想要的——比如「干净机器上一条命令起服务,浏览器能看到页面」——头一张需求件就立起来了。演示要准备的只是一台装了 Python 和 git 的电脑;在哪类机器上验证过,演示页里另有说明。演示目录是全新建的,跑完整个删掉,不碰你现有的项目。后面的派单、施工与收口,演示里同样有现成命令可抄;起完头一张,第二张就是复制粘贴的功夫:换个效果、换组判据,流程一模一样。跑完一遍,你手里就有了一套能复用的起单路数。
