## 这个 skill 是干什么的(人话)

这个 skill 帮你在一单做完并进主线后,派一个独立的审计者按需求逐条核对实际做出来的东西。它交回一份审计件,第一行就是编造、笔误、漏做等几类问题各有几处,你只看这一行和不符项就能决定收单还是返工。不用它,只能听做事的人自己说做完了,编出来的结果和漏掉的活很难被发现。

## 分类

分类:单独装即可用

## 用前填这几个名字

- {{远端主支}}:远端主干分支的完整引用名,审计对它的头量实物;例:origin/main
- {{章程目录}}:各位章程所在的根目录,审计件落在其下派遣者的回执目录;例:_office
- {{拍板人}}:唯一有最终裁定权的人的称谓,审计全符后向他报一句;例:设计者
- {{代码仓路径}}:主代码仓在本机的主检出路径,审计者从这里读远端主干上的实物;例:~/work/demo-app
- {{代码托管远端}}:主代码仓的 git 远端名,审计前先从它取最新;例:origin
- {{工作树根目录}}:一单一工作树统一放置的目录,审计跑命令要落的临时文件放在它下面;例:~/work/_trees

## 什么时候用

- 执行方报「已并线」,需要一次事后核对:这单是不是按需求件做成的。
- 免判卷的单收口后,要一份独立核出的结论才好收单或开返工。
- 返工单再次并线后,要重新核一次(另派新的,不沿用上一次的审计者)。
- 对执行方的收口报告有疑问,想绕开它的自述、直接看实物。

## 步骤

1. 对照「用前填这几个名字」一节,把正文里的对应说法换成你们的实值。
2. 读本目录 `references/top-audit-dispatch.md` 照做。
3. 要复制去派的提示词在本目录 `references/top-audit-subagent-prompt.md`,审计件格式在本目录 `references/audit-brief-template.md`,第 2 步那份用到时会指过去;这三份和别处说法对不上时,以本 skill 为准。
