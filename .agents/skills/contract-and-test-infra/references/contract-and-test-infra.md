# 前后端契约与测试基建

触发：后端模块做完准备交前端、前端对接开工，或估时明显超预期。本件是契约与测试基建完整执行步骤的单一真源；宪法规范仍有效，角色与任务模板链接本件。

1. **估时偏差先核架构。** 先检查协议与测试链，再判断耦合，别先把超时归咎于耦合。某项目界面对接占 40%，而非预估的 15%；核完协议层没问题，根因有三条：后端“做完”没有消费者、一个挂住状态卡死整条测试链、测试没有中间层。
2. **做完必须有消费者。** 每个模块交付都列实际调用它的消费者、输入、输出和一条可复跑记录；没有消费者，就不能宣称模块做完。消费者可以是真实界面或实际调用契约的机器人，只有计划中的未来调用者不算。
3. **状态必须可复位。** 列出每个可挂住状态，各配一条明确的复位命令及复位后判据；复位只作用于授权测试数据，不能让一个残留状态堵住整条测试链。
4. **拒绝必须可读可数。** 每条拒绝路径返回可读拒因键，并有对应文案。从全部拒绝路径核得逐行清单，保证一条路径一行，缺键或缺文案均标为“无拒因”；用 `grep -c '无拒因' <拒绝路径清单>` 量化，目标为“无拒因路径 = 0”。同时核清单覆盖全部路径，不能漏行制造零；零命中时 grep 返回码 1 不算产品失败。逐键核文案，不能靠只走成功路径的测试过关。
5. **补齐机器人中间层。** 每模块至少一条走完整流程的机器人场景；在该场景及其分支中覆盖全部拒因键，保存键清单与覆盖结果。完整场景写不出来，就是没做完；不得把测试链缺口推给前端联调。
6. **契约缺字段走需求。** 契约缺字段是需求，不是 BUG；顺序固定为“后端扩契约 → 重录回放 → 前端再接”。先明确字段含义、缺省值与消费者，再开始对接。
7. **协议保持旧帧兼容。** 新字段只追加尾部，旧帧缺少新增字段时使用约定缺省值；同时保留旧帧与新帧的读取验证，不能插入中间破坏旧布局。
8. **常量进入冷配置。** 可冷更新的新常量按宪法闸 25 进入冷配置，逐键给键名、缺省值与“客户端可见”标记；需要客户端使用的标记为可见并同步读取，结构性的帧格式、枚举、协议号不当作冷参数。
9. **假传输层回放骨架。** 客户端假传输层读取录制帧并按真实契约回放；回放图永远配真登录图，标明各自验证范围。待来源项目第 3 步收口后冻结，先写骨架。
