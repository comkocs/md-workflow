## 这个 skill 是干什么的(人话)

这个 skill 帮你按顶级、困难、日常、轻量四档切活派遣、写提示词并核回报,顶级由主窗本体承担,其余按活派子代理。

蜂巢式派遣把主窗当蜂后、子孙代理当工蜂,工蜂头只在回退线出现:甲类大型仍用短书 + 轻闸,由总监主窗直派施工员 / 读件员 / 审计员(单窗);执行员(困难档子代理或独立窗)只在回退线触发后用。主窗定边界并验收,施工与核验各交独立子代理,不拿一句「做完了」当放行证据;回退线上的执行员只编排派遣。

## 分类

分类:单独装即可用

## 用前填这几个名字

- {{拍板人}}:唯一有最终裁定权的人的称谓,开窗确认本项目各档可用模型;例:产品负责人。
- {{远端主支}}:远端主干分支的完整引用名,子代理的底数按指定提交量;例:origin/main。

平台与模型映射见本目录 `references/模型对照表.md`,由总监开窗识别后填「本项目实填」列;派单、任务书、台面只写档位词,不写具体模型名。模型换代只更新对照表,不改分档规矩。

## 四档与升档

| 档 | 做什么活 | 谁 |
|---|---|---|
| 顶级 | 读订宪法与章程、推翻已判结论、多文件语义判断、与拍板人对接需求 | 主窗本体,不派子代理 |
| 困难 | 跨文件状态机 / 协议编解码 / 持久化 / 账本与号源 / 解合并冲突 / 完整审计 / 起草任务书与需求件 / 回退线上的执行员 | 子代理 |
| 日常 | 普通改码、跑 build 与点名用例、轻审、格式转换与登记、单文件小修 | 子代理 |
| 轻量 | 扫盘、读大件总结、抄数、校验和、按清单搬运、跑固定脚本;不审码、不审图 | 子代理 |

子代理交回的东西审计不过,或同一件活连败两次,同活升一档重派(轻量 → 日常 → 困难),记进任务书进度件;困难档连败两次,报总监本体接手或改题,不把顶级当子代理档。

## 什么时候用

- 总监主窗或回退线上的执行员要派子代理,需要切活、选档或写提示词。
- 收到「做完了、可以合并」,准备核验、放行或评估产出质量。
- 平台没有子代理、只能自己做时,仍按切活、权限边界与回报格式走。

乙、丙与甲类中小由总监主窗直接派日常 / 轻量档子代理;甲类大型仍用短书 + 轻闸,由总监主窗直派施工员 / 读件员 / 审计员(单窗);执行员(困难档子代理或独立窗)只在回退线触发后用(甲类大型 = 预计改动 ≥ 1,500 行或跨 ≥ 10 文件;回退线 = 预计长单且总监要换窗、总监上下文超 70 万 token、幻觉返工或断线续不上、并线冲突或跨仓、{{拍板人}} 要求双窗)。

## 步骤与自包含原料

1. 读 `references/delegation-steps.md`,先切调研与施工,一个子代理只背一件活,同一文件只归一个子代理。
2. 按四档用途选档,用 `references/模型对照表.md` 查平台映射;顶级事项留主窗,困难事项不降成日常。
3. 按活取本目录五类定义:轻量读件用 `references/读件员.md`,日常施工用 `references/施工员.md`,五类难活用 `references/高阶施工员.md`,回退线编排用 `references/执行员.md`,核验用 `references/审计员.md`(轻审日常,完整审计派遣时传困难档)。
4. 定义的 `model` 按本项目实填列替换。Claude 平台把定义拷进项目的 `.claude` 目录下的 `agents` 子目录;codex / zcode 无此目录,定义正文逐字贴作派遣提示词首段。再写死权限、底数、进程、验证与回报格式。
5. 先核证据再读结论,只收模型首行与三行回报;不采信自述。独立核验不复用施工上下文,审计不过或同活连败两次按上面的规矩升档。

以上原料都在本目录内,独立安装不需另取整套工作流。没有「总监窗」「执行员」「台面」这些叫法的项目,分别换成派活主窗、回退线编排者与任务登记处,分工边界不变。
