# 收口报告起草 · 精简步骤

模板在本 skill 目录的 `references/closeout-report-template.md`(下称「模板」),骨架、「写 / 不写」表和量字符的命令都在里面。本文件只列步骤,每步细节回模板读,不在这里抄;两边对不上时以模板为准。

1. **判该不该写**:单做完才写收口报告;做不完不写报告,改写 0 号交接件(用 `window-handoff-drafting` skill);丙档不写报告,只回一行回执。细节见模板「规格」。
2. **定谁起草**:交子代理做,平台没有子代理就自己做;执行窗本体只核、不重写正文。收口要读的大件(对账表、进度件)只让起草者读,本体只收结论。细节见模板「规格」。
3. **抄骨架**:整段抄模板「骨架」填空;四个二级标题逐字照写,不加序号、不改字,全文只留这四块。细节见模板「规格」第一条与「骨架(下面整段抄走填空)」。
4. **逐块填**:照模板表格的「写 / 不写」两列填。结论一行不用没有对象的词;事实段只写可核的事实,每个数带出处,构建与全回归结果连基点提交号;需总监动作 3~5 条,每条写清谁做、做什么、为什么。细节见模板「每块写什么、不写什么」与「骨架」。
5. **收尾三问**:第 1 问给出让用户(内部单写 {{拍板人}})亲眼看到改动的命令或路径;第 2 问只写一处最没把握的及怎么验;第 3 问逐条写自主假设落在哪个文件哪个符号,自定的数标明是自定、不是裁定。答不出写「无」并说为什么。细节见模板「骨架」的「收尾三问」。
6. **挪走不进报告的**:红集逐名对账进审计件;跨窗协调进对话线小表;给 {{裁定簿路径}} 的补登条文单独成件;流水账、过程复述删掉;做不完的只归「事件还没发生 / 归别位」两类之一,写进需总监动作。细节见模板「不进收口报告的」。
7. **量篇幅**:按字符量,不按字节量(部分终端的 `wc` 类命令对中文只数字节,会高估约一倍);全文 ≤{{收口报告字数上限}} 字,事实段另有上限。量法命令与传路径的注意点见模板「规格」第二条。
8. **落盘**:写到 `{{章程目录}}/<位名>/回执/<单号>_收口报告.md`;裁定簿补登件同目录另起一件。细节见模板「规格」与「不进收口报告的」。
9. **本体核**:哈希用 git 核、数字用命令核、文件名用列目录核;本体不重写正文。细节见模板「规格」。
