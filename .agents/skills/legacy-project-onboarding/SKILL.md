## 这个 skill 是干什么的(人话)

这个 skill 帮你把旧项目或旧窗口接进当前窗口:先让老窗口导出一份记忆,核清兼容与冲突,再按已有授权只补缺的,老项目现有规矩和真源优先。它把导出、导入、选范围、第一窗四步各给一段自包含做法。不用它,常见的坑是新窗口一上来就翻用户目录、拿模板盖掉老规矩,或没拿到授权就动老项目文件。

## 分类

分类:单独装即可用

## 用前填这几个名字

- {{导出件路径}}:老窗口把记忆导出写进的新文件位置,由用户指定;除这份新文件外,原项目文件一字不动。
- {{已授权范围}}:用户明确授权可读、可改的文件、目录与命令;清单之外不动手,已给过的许可不重复索要。

## 什么时候用

- 一个有历史的旧项目要从旧窗口或别的工具接到当前窗口继续做。
- 老窗口还在、能配合写一份导出;或只拿到零散文件,要先判能不能接、缺什么。
- 老项目有自己的规矩、台账、术语,直接套新模板可能起冲突。
- 接完要做第一窗,不知道哪些照旧、哪些照新做法做。

## 步骤

1. 守住底线:AI 不翻用户目录;不把方法文档塞进老窗口;术语用老项目的叫法;只用用户给的导出件和明确点名的文件或目录,不自行枚举。冲突不由 AI 擅自选边,不清楚就标明缺口;{{已授权范围}}够用就继续做对应工作,不重复要许可。
2. 导出:把下面这段自包含请求逐字贴给仍掌握上下文的老窗口,导出件写到 {{导出件路径}}——「请把你当前已知的项目现状写成一份记忆导出,给没有上下文的新窗口接手,全文不超过六千字。只新建我指定的导出文件,不改其他文件,不为补全内容扫描目录;仅使用当前上下文和我明确提供的材料;不知道的写不清楚,不要编造。写清:项目做什么、给谁用、当前阶段;硬规矩原文及出处;现有协作与术语;仍在办的事项、负责人、判据、证据、阻点与下一步;仍成立的坑;关键文件的精确路径和优先级;这次没有带走、会影响接手的内容。保留已验证的命令、运行目录、期望输出,并明确哪些事尚未发生;历史流水只写位置和体量,不搬全文;篇幅不够先删重复、过期事项和次要坑,硬规矩不能删」。导出后按字符数复核不超六千,超了让老窗口压;确认除指定导出件外没有额外写入。
3. 导入:新窗口先只读本 skill 与导出件,给一屏接手报告,本轮不改老项目;逐项写已理解的目标与术语、当前有效规矩、最先接的未完事项、能验证的完成定义、规矩冲突与缺口、导出明确没带的内容。没证据写尚未验证,不把读了导出说成已接手跑通;用户已授权复验时,只沿导出给的精确位置跑所列命令,会写缓存或产物的先放获准的隔离位置,并记录命令、输出与前后状态。
4. 核兼容与冲突:称谓不同但职责相同的(如工单、位、工位)先列映射;现有规则与新方法实质冲突时,把冲突原句、结果差别与建议一次说清交用户定;模板和名词差异不当必须改制的问题。
5. 选接入范围:默认只补缺的,保留老项目目录、术语、台账与工作方式,只补缺的判据、可复验证据、交接字段或真源指针;全合并只在用户明确选择时做,先给具体文件清单、规则映射与改前改后片段;也可什么都不改,只交接不动结构。装工单台是独立选择,不是导出导入的前置;旧台账先不替换,不能让旧库与新台账同时受理派单。要装钩子与子代理时:两道钩子按产品自带的安装说明合入,CLAUDE.md 模板拷到开窗目录、替换路径占位、保留已有权限与规则;子代理定义在 Claude 平台拷进项目 .claude/agents/ 即装好,codex / zcode 平台把定义正文逐字贴作派遣提示词首段,派单只写档位词(顶级 / 困难 / 日常 / 轻量);识别到 codex 平台的,读 ~/.codex/config.toml 的 [agents] max_concurrent_threads_per_session,键缺或值低于 20 先备份成同目录 config.toml.bak_<日期> 再改成 20 并一句话告知用户,不低于 20 不动。
6. 第一窗:接管老项目不出三件(思维导图、产品文档、原型图或架构图),不做拆解清单,不判最先进做法;技术一律按用户现行做法,用户点名老做法或要接现有系统时照用户的;但判规模与代码规范、素材管理照首次需求对接窗的做法做,规模用现有代码量判。
7. 收口自查:导出件在限额内;接手者能从导出定位当前目标、规矩和未完事项;已获准的验证有真实命令与原样输出;未验证、待裁定、未发生的事分别说明;报告最后写下一步由谁做、从哪份文件起手、达到什么判据算做好。
