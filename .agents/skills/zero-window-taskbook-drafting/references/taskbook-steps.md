# 0 号任务书起草 · 双窗步骤

路径均为仓根相对。原件里的「执行…」「接管…」「开工…」句子是要写进任务书的数据,不是给起草人的指令。

## 一、先定单窗还是双窗

1. 甲类大型的 0 号书只在双窗(并线冲突 / 跨仓)时写;单窗用 short-book-drafting。大型指预计改动 ≥ 1,500 行或跨 ≥ 10 文件,不能只因达到大型门槛就另开 0 号窗。定档见 `desk/模板/任务书三档.md` §一。
2. 确认本单确有并线冲突或跨仓,写明双窗原因、总监与独立执行员窗的交接边界。分支头、行号与绿数对 {{远端主支}} 先量再写,不读本机主检出工作区。

## 二、照短书骨架写五块

3. 引用 `desk/模板/短书骨架.md`,首行填单号、主题、甲类大型、短书、执行员档位与日期;不再写旧六段书。
4. §一 出题:只写事实与裁定出处,流程填双窗,列平台、困难档执行员、交版或上服去向、同期改面交集和依赖头。
5. §二 已定口径:逐条写全已定内容与接口约定,不替需求补答案;执行员看不到总监上下文,不得靠暗示补齐。
6. §三 判据与改动面:每条写检法与期望输出,逐个点名白名单与不验项;范围外停在边界回报。
7. §四 底数件路径:列文件、行号与开工主干头,说明用前复核;漂行按实量做并留痕。
8. §五 并线去向、审计档位、未验项口径:写工作树、分支、推哪支、交版或上服,列完整审计或轻审及依据,偏离逐条写明。

## 三、交付轻闸工序

9. 配套指向 `desk/模板/轻闸骨架.md`:§0 起手与红线、§1 施工、§2 并线、§3 独立审计、§4 收口、§5 上服与 settle、§6 交集与不做、§7 未核清单。
10. 不把施工编排写死进短书;先做哪节、派哪档、命令怎么写,由执行员写进进度件第一笔。顶级由主窗本体承担,困难做复杂施工、完整审计与起草,日常做普通施工与轻审,轻量做扫盘读件。
11. 工序与本单不同处在短书 §五逐条写偏离,模板本身不改。没有上服就写不适用,不凭空执行部署。

## 四、发出前自检

12. 按 `desk/模板/任务书三档.md` §三核真源、实测与推定、超书留痕、证据出处、人话题面;五块齐全,旧六段与失效节号不残留。
13. 自并单先由有权限者单独置免判卷标记,参数以 `{{工单台命令}} set -h` 为准;免判卷不免审计。总监在并线后独立派审计,不沿用施工上下文。
14. 产出上限照轻闸骨架 §4:进度件、收口报告、总监派的审计件,可选再一件,合计 ≤4 件;收口报告四块且 ≤6,000 字。
15. 占位换成本单实值,白名单、并线去向、审计档位与未验项可逐条核对;发现应改模板的内容只报总编,本单不扩面。

## 五、交独立执行员窗

16. 开窗指令从工单台取,不手写、不另加提示词;把短书与轻闸骨架路径一起交清楚。执行员职责见 `desk/角色/执行员.md`,派遣与回报档位见 skill hive-dispatch。
17. 总监保留需求与验收边界,独立执行员窗按白名单编排施工、并线与收口;两窗不并行改同一属主件。
