# 工程坑清单

用法:按症状找到下面对应的一类,先跑「检查」里的命令,再按「判读」下结论;没跑检查前不改代码、不下结论。回报写清核了几个文件、在哪个提交上核的。来由:多窗并行实践中踩过。

## 1. 编辑工具悄悄加 BOM

- 症状:构建和测试都绿,差异里却有一处首行改动,新旧两行肉眼一样;或并线冒出说不清的冲突、按行首锚定的搜索一条不中。
- 检查:核提交里的 blob 首字节,不核工作区文件:`git show HEAD:<路径> | od -An -tx1 -N3`。成批时,对 `git diff --name-only <基点> HEAD` 列出的每个文件各跑一次。
- 判读:打出 `ef bb bf` 而该文件原本没有 BOM,就是被加了,另起一笔提交去掉,不用 `--amend`。原本就该带 BOM 的文件(如给旧版 PowerShell 用的脚本)只要求改前改后首 3 字节相同。回报写「核了 N 个文件,新增 BOM 0 个」。

## 2. 子代理读到旧工作树

- 症状:子代理报的行号、「这个分支没并」「那处没人调用」说得很具体,一核对却不符;事后发现它读的树落后好几笔,甚至不是同一个仓。
- 检查:在它读的目录里依次看仓根(`git rev-parse --show-toplevel`)、远端(`git remote -v`)、当前提交(`git rev-parse HEAD`);再 `git fetch` 后跑 `git rev-list --left-right --count HEAD...{{远端主支}}`,输出两个数,右边那个是本地落后的笔数。
- 判读:仓路径或远端不对、HEAD 游离、落后数不为 0,它的结论一律作废,改用 `git show {{远端主支}}:<路径>` 按远端重核;三样都对且落后为 0 才采信。要整套取某提交的文件,先 `GIT_INDEX_FILE=<临时文件> git read-tree <提交>`,同一变量下接着执行 `git checkout-index --all --prefix=<空目录>/`,不碰共用的树。每条结论都带仓路径与提交短号。

## 3. 部署闸抓出运行时小版本漂移

- 症状:本机测试全过,服务器上同一份代码却红几条;红处与本次改动无关,多半在比对标准库吐出的原样文字。
- 检查:两边各打一次运行时版本(`python --version`,别的语言用对应命令)对比;逐条读失败断言,分清它钉的是本次改的行为,还是标准库输出的字面格式。
- 判读:小版本不同、断言又钉着字面格式,就是漂移:把断言放宽到行为层(如只断状态码或关键字段),再故意弄坏行为确认它仍会红,防止放成永远过。本机与服务器结论相反时以服务器为准,部署前检查不因本机绿了就跳过。

## 4. 共享检出的 git 纪律

多个窗口或子代理共用一个检出、状态里冒出不是自己改的文件或推送被拒时,检查与判读都照 shared-checkout-safety 这个 skill 做,本件不重复。

## 5. shell 与编码坑

- 换行符。症状:多行替换报「零处改动」其实没匹配上,或编辑后整份文件看着换行全变了。检查:`git ls-files --eol <路径>`、`git diff --cached --stat`。判读:索引侧 lf、工作区侧 crlf 时,用 LF 写的锚点在工作区必然落空,换成工作区的换行再替换并读回命中数;暂存区改动行数远少于全文件行数,只是显示差异,提交时会归一化,不算事故。
- 路径写法。症状:上一步成功、下一步说找不到文件或工具;原生程序读不到 shell 刚写的文件。检查:`printenv PATH | tr ':' '\n' | head -20`;再用 `python -c "import os;print(os.path.exists(r'<路径>'))"` 以原生程序验同一路径。判读:盘符被冒号拆成 `D` 与 `/…` 两段,或 `/d/…` 被原生程序当成当前盘下的 d 目录,就是写法混用:统一写 `D:/目录/文件`,依赖 PATH 的程序改写全路径。
- 旧版 PowerShell。症状:含中文的 .ps1 在不相干的行报语法错。检查:`od -An -tx1 -N6 <脚本>`。判读:开头没有 `ef bb bf` 是缺 BOM,有两组是叠了两个;别照报错行号改代码,读用 utf-8-sig,写时补恰好一个。
- 命令被吞或改写。症状:写进文件的内容少了反斜杠、变量被展开,或反引号里的字被当命令跑了。检查:写完立刻读回比对。判读:对不上就改用写文件工具落盘,不用未加引号的 heredoc 或双引号包反引号。
- 退出码。症状:命令报 0 但产出物不对。检查:去掉 `| tail` 之类的管道重跑,或直接核产出物。判读:接了管道时拿到的是最后一个命令的退出码,0 不等于做成。

## 6. 抖动测试集怎么判

- 症状:整包偶尔红一两条,重跑就绿,或每次红的名字不同。
- 检查:在干净检出(`git status --porcelain` 输出为空)上连跑 `{{全回归命令}}` 两次,各存一份输出;两次的失败名各自排序后 `diff`;把嫌疑子集(碰数据库、端口、文件锁的)单独跑;还拿不准就开一棵不含本次改动的对照树,同条件跑出基线。
- 判读:两次失败名完全一致才是真问题;名字每次漂、拆开单跑又全过,是环境抖动。先红后绿的自检类测试按红处理。验收只写「本次相关那组测试全过」,不写整包全绿,也不列固定豁免名单。
