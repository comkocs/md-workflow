# 接通与故障(所有窗开工先做)

命令一律写成 `{{工单台命令}} <子命令>`;任意子命令可加 `--json` 给机器读。下文「原件」= `core/tools/tickets/README.md`,只读点到的那一节。

## 开工三步

1. 自检一行:`{{工单台命令}} env`,看本机还是远程、连哪台、令牌文件在不在、配置从哪一级取到。要查服务端协议版本才加 `--probe`(只有这时出网)。
   - 入口填的是只连本机的那种时,这里永远显示本机模式;要连服务器的窗换用连服务器的入口(见 SKILL.md「用前填这几个名字」)。
2. 没接上先接:总监发的 `remote.env` 放在 `<仓上一级>/tasks/tickets/remote.env` 会自动接上;放别处就设环境变量 `TICKET_ENV` 指向它(正斜杠路径)。两个 shell 的现成写法在原件里,写任务书第 0 步时从原件抄,别把键值抄死。细节见原件「员工窗怎么接通道」。
3. 核通道:`{{工单台命令}} receipt <一个确定在服务器上的单号>`,打得出这张单的真标题和状态才算连着服务器;打不出就先修通道再干活。细节见原件「远程模式怎么确认自己连的是服务器」。

## 配置从哪取

- 四级,前面取到就停:环境变量 `TICKET_REMOTE` / `TICKET_TOKEN_FILE` / `TICKET_CA_SHA256` → `TICKET_ENV` 指的文件 → 仓根往上推算的 `tasks/tickets/remote.env` → 都没有才是本机模式(stderr 打一行「本机模式(未接通道)」)。
- 配置找到了但用不了(缺令牌文件等)会直接拦下并说缺哪样,不会悄悄退回本机。
- `--local` 强制本机,只给测试与离线自查用。
- 令牌只放文件里,不进 git、日志、工单、聊天。
- 细节见原件「员工窗怎么接通道」中段。

## 看懂退出码与回话

- 退出码 2:被闸拦下,错误正文是人话,照它说的改。
- 退出码 3:远程不可达,**你看到的不是服务器上的数据**,不要据此判断、建单或报障。设 `TICKET_ALLOW_STALE=1` 能看本机旧快照,但仍退 3。写操作远程不可达一律硬报错,不落本机。
- 本机模式找不到单,回话会提示先接通道;远程模式说「服务器 <主机> 上没有这张单」才是真没有。
- 细节见原件「远程模式怎么确认自己连的是服务器」后半。

## 版本不一致

- `receipt` 末尾显示客户端与服务端协议版本;两者不同时新开关可能被降级。建/改单后任务书校验显示「待回核」的,等服务端更新后由所属总监位重跑一次 `set <单号> --taskbook <同一路径> --by <所属总监位>` 回核。细节见原件「协议版本、探测与安全降级」。
- 服务端还是旧版时 `receipt` 没有末行四项摘要、`state get` 被拒,不是本机坏了。细节见原件「当前值面」末段。
- 本机命令行或服务端版本旧只在 stderr 打一行警告,命令照样生效,不要为此停车。细节见原件「非业务闸不停车」第 ⑤ 条。

## 远程交板的本机核验

- 远程模式下 `submit` 的交付项由你本机逐个核存在,核齐才发请求,结论记成「交付项本机核验:N/N 齐」;少一个就在本机报错。图片类交付项仍由服务端核。细节见原件「协议版本、探测与安全降级」末段。

## 两个入口

- AI 工位窗用命令行写单、推状态、发言、看未读。
- 设计者与总编排位在浏览器里看台面、答复、拍板:`{{工单台命令}} serve --open` 起本地服务并打开网页。细节见原件「怎么开始」「两个入口」。
- 起服务器、上服、部署闸不在本 skill,见原件「上服：三道前置闸和一道后置闸」。
