# 复检复验、实机复验与 0 号收口

下文「原件」= `core/tools/tickets/README.md`,只读点到的那一节。

## 当前值面(复检位、总编排位)

1. 读:`{{工单台命令}} state get`(一份 JSON)或任一 `receipt` 的末行。各位只读不抄。
2. 改:只有复检位与总编排位能改,`{{工单台命令}} state set <键> <值> --by <位名>`。键只有 `judging_resolution`、`deploy_head_engine`、`deploy_head_server`、`walk_run_speed`、`pending_shared_tools`;每个键怎么写见原件表格。没人填的项显示「未填」,工具不替你填。细节见原件「当前值面」。

## 复验与并线落账

3. 复检席复验:`{{工单台命令}} verify <单号> --result <过|退> --by <复检位或其员工编号> --gates "<跑了什么、结果是什么>"`;退时 `--gates` 与 `--evidence` 至少给一个。内部单交板带齐六项机器闸报告且全过的会自动记复验过,复检只看闸输出。参数见 `verify -h`、`submit -h`。
4. 三方互斥:复检人、执行员工、判卷人不能是同一人。本位自有单(所属位、判卷人、复检人是同一个位名)例外放行,落库记成「<位名>(自记·待设计者终验)」。细节见原件「本位自有单的并线」前半。
5. 并进主干后落「已合并」:`{{工单台命令}} merge <单号> --by <位名>`;署名要求以 `merge -h` 与报错为准。

## 实机复验(live)

6. 每次 `live` 必写 `--shot 同图|独图|免独图`。同图 = 整批共用一张部署后真登录图;独图 = 专为这张拍。图本身可选,给了就挂成「真登录」图。
7. 一图批量:`{{工单台命令}} live <首张单号> "<真登录图路径>" --batch <单号2> --batch <单号3> --shot 同图 --by <复检员工编号>`;某张状态不对只跳过那张。
8. 玩家可感知单用同图记「待独图」,之后 `live <单号> "<图>" --shot 独图 --by <复检员工编号>` 补成独图;`{{工单台命令}} list --shot-pending` 看还欠独图的单。
9. 免独图(判语写明无玩家可见产出的诊断类单、验证对象已退役的单):只给「实机复验过 + 待独图」的单,只许复检位或总编排位署名,`--reason` 必填,不能配 `--batch`。
10. 交板时标了「欠真登录图」的单,上服后 `{{工单台命令}} attach <单号> "<图>" --origin world --by <位名>` 补图(标记自动清)再 live。
11. 第 6~10 条细节见原件「live 的同图、独图与一图批量」。

## 终态与自动退役

12. 内部单「已合并」起就不再老化、不算卡住;玩家可感知单要 live 过才算到头。细节见原件「内部单并线即到头」。
13. 单进终态(关闭、作废、实机复验过、内部单已合并)时,执行方不是固定工位且手上没别的在办单,工具自动把他收窗;阻塞不算终态。收错了 `{{工单台命令}} staff reopen <员工编号>` 拉回。细节见原件「到终态自动退役」。

## 0 号自并收口(免判卷单)

14. 前提:所属总监位已对该单置了模块免判卷(见同目录 `director-dispatch.md` 第 12 条)。免判卷单不走 `judge`,三方互斥闸不生效。
15. 0 号窗 `submit`(带验证命令、原样输出、提交号)后收口:`{{工单台命令}} settle <单号> --by <员工编号> --fact "<一行事实>" --main-commit <合并提交号>`;上了服再带 `--deploy-head <部署头>`。参数以 `settle -h` 为准。
16. settle 后内部单落「已合并」,可感知单落「实机复验过」;顶级审计全符后,内部单由总编排位 `live` 一次再由所属总监位 `close`,可感知单由所属总监位直接 `close`。
17. 0 号窗自己并自己推,主干里没有合并提交;核它进没进主干只认提交的祖先关系,别按搜合并提交判。细节见 `desk/memory/种子/2_0号窗纪律.md` 的 2.20 节。
18. 第 14~16 条细节见 `desk/角色/0号包干窗.md` 的「收口:并线、上服、交板」;并线与上服本身的步骤见 `.agents/skills/merge-and-deploy/references/merge-and-deploy.md`。
