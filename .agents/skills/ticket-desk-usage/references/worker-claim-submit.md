# 员工开工、卡住与交板

先照同目录 `connect-and-errors.md` 接通。下文「原件」= `core/tools/tickets/README.md`,只读点到的那一节;`<单号>` 形如 T- 加六位数字,`<员工编号>` 是名册里你的编号。

## 第 0 步

1. `{{工单台命令}} receipt <单号>`:看标题与状态;末行是当前值面四项(判据图尺寸、部署头、走跑速度、已改未并公共工具)。**读它,不要抄进自己的件**。细节见原件「当前值面」。
2. 单是「返工」态时,`receipt` 会带出返工次数、判卷人、判语全文和最近一条返工原因;照判语改,别拿旧任务书再交一遍同样的板。细节见原件「远程模式怎么确认自己连的是服务器」中段。
3. `{{工单台命令}} inbox --slot <本位> --for <员工编号>`:看未读;末尾「★你位当前待答 N 张」是欠答清单。见同目录 `threads-and-inbox.md`。
4. 固定工位:开窗指令会点名工位记忆件,先读它;里面的分支头、绿数、行号只当线索,先核主干头、在自己的工作树跑一次全量拿当下绿数,对不上以现在为准并在单里报一行。细节见原件「固定工位与工位记忆」。

## 认领

5. `{{工单台命令}} claim <单号> --by <员工编号>`,落「已认领」。返工单换了任务书也是再 claim 一次。

## 卡住了

6. 先分清这条闸拦的是「活没做好」还是「字没写对」:
   - 业务(真源缺、接口对不上、判据不达、测试红):`{{工单台命令}} block <单号> "<原因>" --by <员工编号>`(默认 `--kind 业务`),单进「阻塞」等人解。
   - 非业务(交付项写法、路径前缀、任务书待回核、远端滞后、命令行版本旧):同一条加 `--kind 非业务`,只记一行、状态不变,**接着做,不等答复**。
   - 细节见原件「非业务闸不停车」。
7. 只想留一句话、不改状态:用带 `--ref <单号>` 的 `say`,见同目录 `threads-and-inbox.md`。
8. 交付项只是写法不对(后缀、工作树与主检出路径前缀)可自己改:`{{工单台命令}} set <单号> --deliverable "<项1>" --deliverable "<项2>" --by <员工编号>`。只许改写法不许换成别的文件;`--deliverable` 整条替换,原有各项都要写上。细节见原件「非业务闸不停车」第 ② 条。

## 交板

9. 先核齐交付项:每一项都要在当前检出里真的存在(远程模式由本机逐项核)。缺了会报出一条完整的 `set` 命令;员工没有改单权,把它原样发给报错里点名的所属总监位,别删参数。细节见原件「建议窗口（开窗工具建议）」中段。
10. 按单型交:
    - 内部工具单:`{{工单台命令}} submit <单号> --evidence "<一句话>" --verify-command "<验证命令>" --raw-output "<原样输出>"`,后两项缺一不能交。有六项机器闸报告的加 `--gate-report`(项名见 `submit -h`)。
    - 玩家可感知单:`{{工单台命令}} submit <单号> --evidence "<一句话>"`;真登录图选填,附图先跑 `{{工单台命令}} attach <单号> "<图路径>" --origin world --by <员工编号>`。想附却够不着真实运行环境取不了图,加 `--shot-blocked "<机器实况/试过什么/卡在哪步>"`,并同时带验证命令与原样输出。
    - 细节见原件「交板时的两类证据」与「建议窗口（开窗工具建议）」后段。
11. 给下一窗留话:`submit` 加 `--handoff "<底数与坑,一行一条>"`,只写真源在哪、哪个数别信、下一窗从哪起手,不写流水账。细节见原件「固定工位与工位记忆」。
12. 单型标错(内部与可感知)不要自己翻开关,更不要署所属总监的名;请所属总监位改。

## 交完之后

- 固定工位交板后工具会自动重刷记忆件;重刷失败只多一行提示,不影响交板。
- 单到终态时,非固定工位且手上没别的在办单,名册会自动把你收窗。细节见原件「到终态自动退役」。
