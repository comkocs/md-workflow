# 总监派单、改单与解卡

下文「原件」= `core/tools/tickets/README.md`,只读点到的那一节。`<本位>` 是你的总监位名;改单与作废只认该单所属总监位或总编排位。

## 建派单前

1. 先把任务书 md 落盘;`--taskbook` 会在你本机核文件确实存在。猜不到单号就在路径里写 `{ticket}`,取号后自动替换。细节见原件「任务书路径与 `{ticket}` 占位符」。
2. 执行员工要本位在册在岗:开新窗登记 `{{工单台命令}} staff new --slot <本位> --tool <模型名或 待定>`;名册默认只列在岗,`staff list --all` 看全量。

## 建派单

3. `{{工单台命令}} new --type 派单 --slot <本位> --title "<标题>" --source "<真源指针>" --consumer "<实机消费者>" --deliverable "<仓相对路径>" --tier <甲|乙|丙> --internal --assign <员工编号> --taskbook "<任务书路径>" --by <本位>`
   - `--internal`(内部工具单)与 `--player-facing`(玩家可感知单)必须二选一明写。
   - `--tier` 必填;丙档另要 `--context-lines`(不超过 2000)并用丙档模板。
   - `--deliverable` 可写多次,每项写成路径不写叙述句;建单只核形态,文件还不存在只提醒、照常建,存在性留到交板核。
   - 建议开窗工具:`--window <合法值>` 或在标题开头写全角方括号标签;只是建议不是硬闸,合法值见 `new -h`,怎么选见原件。
   - 细节见原件「建议窗口（开窗工具建议）」「两个入口」。
4. 建成后命令行打印三行开窗指令(与卡片一致);任务书路径为空只打补路径提醒。固定工位的单会自动带「先读记忆」。

## 建完要改

5. `set` 改口径:任务书路径、指派给、真源指针、正文、消费者、交付项、单型、建议窗口、任务档。只许「新建 / 已认领 / 返工」三态。
   例:`{{工单台命令}} set <单号> --taskbook "<新路径>" --by <本位>`
   - `--deliverable` 与 `--source` 都是整条替换,原有各项要写全;`--source` 全空会被拦。
   - `--assign` 只收本位在册在岗的员工。
6. `void` 一笔勾销:`{{工单台命令}} void <单号> --reason "<错在哪>" --by <本位>`,只许「新建 / 已认领 / 阻塞」三态。
7. 交了板的单(待判及以后)既不能改口径也不能作废:要否掉走判退,判过之后只能关闭。
8. 第 5~7 条细节见原件「一张单建完之后还能改什么」。
9. 单型标错:`{{工单台命令}} set <单号> --internal --by <本位>`(或 `--player-facing`)翻回来;这一个开关设计者也能翻。细节见原件「建议窗口（开窗工具建议）」后段。
10. 员工交板报缺交付项、把现成 `set` 命令发给你:核一眼后原样跑,不要删看似无关的参数。

## 解卡

11. `{{工单台命令}} unblock <单号> --by <本位>`:一律落「返工」,单号、断点、返工次数全留,已开窗戳记清掉,单子回到设计者「要你传达的」。要换书就 `set <单号> --taskbook "<新路径>" --by <本位>`,员工再 claim 一次。细节见原件「`unblock` 一律落「返工」：换书不换号」。

## 模块免判卷

12. 设计者取消了本模块的判卷与复检时:`{{工单台命令}} set <单号> --exempt-judging 是 --by <本位>`,之后执行方可一步收口(见同目录 `review-and-wrapup.md`)。这个参数单独一条命令跑,待判、待复检、阻塞态也能置。参数见 `set -h`。

## 其他

13. 导出任务书:`{{工单台命令}} export <单号> --out "<目标路径>"`;不写 `--out` 落到本位 `_office/<位名>/任务书/`。细节见原件「导出任务书」。
14. 设计者点【已开窗】会在单上记轮次、时间、实际模型;判退、`rework`、`unblock` 都会清掉它,让单子回到「要你传达的」。细节见原件「「已开窗」字段」。
15. 各状态停多少小时算卡住,见原件「状态进入时间与停滞告警」的阈值表。
