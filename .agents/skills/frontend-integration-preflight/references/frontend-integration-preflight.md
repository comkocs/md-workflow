# 前端对接开工前三样检查

触发:前端准备接某个后端模块、还没开工对接那一刻。三样逐样核到具体条目,不凭后端一句「做完了」就开工。

## ① 契约齐

- 怎么核:向后端要接口文档和该模块的拒绝路径清单。把前端这次要用的每个字段逐个在文档里找到,再对照后端实际返回,核名字、类型、含义、缺省值;逐条拒绝核拒因键和界面要显示的文案。
- 核到什么算齐:要用的字段在文档里一条不缺,且与实际返回对得上;每条拒绝都有拒因键和文案,缺的条数为 0。

## ② 可复位

- 怎么核:向后端要该模块所有会挂住的状态(如等待中、锁定、处理到一半)和各自的复位命令;在测试数据上把每个挂住状态造出来一次,跑复位,看是否回到起点。
- 核到什么算齐:每个挂住状态都有复位命令;从任意状态跑复位都能回到起点,且有办法确认已回到起点。

## ③ 可离线

- 怎么核:先列出这次要做的目标界面;断开真服,只靠后端给的回放或自动场景,把每个目标界面各走到一次。
- 核到什么算齐:列出的目标界面全部不连真服就能到达,到达后显示的数据与接口文档对得上。

## 结论

三样都齐才开工。缺一样就退回后端、不开工。退回时写清缺哪样、缺哪几条;后端补齐后,三样从头再核一次。

## 这是一道闸

拦:对接到一半才发现缺字段、卡在挂住状态回不去、每试都得连真服。

回口:退回后端写清缺哪样哪条,补齐再开,其间做别的。

拆除:后端交付已把三样列为必含项并机器核过时可省。

后端怎么补齐这三样,若也装了 contract-and-test-infra,照它做;本件不重复。
