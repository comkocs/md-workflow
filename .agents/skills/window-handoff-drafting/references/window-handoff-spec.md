## §7 换窗接管

### 7.1 三种文件各管什么

| 文件 | 谁的 | 管什么 | 篇幅上限 | 模板 |
|---|---|---|---|---|
| 总编现状件 `接管_现状.md` | 总编 | 全局现状、有效裁定、下窗待办;指针 | ≤24,000 字符 | `references/chief-editor-archive-template.md` |
| 总监现状件 `接管_现状.md` | 每位总监(平台位同式)一份 | 本位现状、下窗待办;指针 | ≤24,000 字符 | `references/director-takeover-template.md` |
| 0 号交接件 | 一单一份 | 这张单做到哪、下一棒从哪接 | ≤6,000 字 | `references/zero-window-handoff-template.md` |

三份共同铁律:**只写现状与下一步,不复述历史**。历史用搜索(`git log`、归档目录),不整读;不写数值推导过程,不逐句转录对话,不写本窗流水账(流水只追加到归档件)。现状件只两节:§一 现状 / §二 指针;本位口径与规矩写章程(现行声明四节:本位管什么 / 真源表 / 开窗步骤 / 规矩只引号),不写进现状件。

来由:某大型多人在线项目最早一版归档(2026-08-25)247 行,过半篇幅是数值推导、设计者原话逐句转录和「本窗做了什么」;从第二十版起改成只写现状与下一步,稳定在 64~70 行,接手窗读得完。

### 7.2 谁起草、谁核

| 文件 | 起草 | 核 |
|---|---|---|
| 总编现状件 | 总编本窗(上下文已很大时派子代理起草) | 总编本窗 |
| 总监现状件 | 总监本窗(同上) | 总监本窗 |
| 0 号交接件、收口报告 | **子代理** | **0 号本体只核**:哈希用 git 核、数字用命令核、文件名用 ls 核;本体不重写正文 |

- 收口时要读的大件(>50KB 的对账表、进度件)只准子代理读,本体只收结论。
- 核的结果写进交接件末尾「核对记录」:命令与输出原样贴,不写「已核」两个字了事。

来由:2026-09-19 前后某项目一张单的第三棒:子代理写的代码全对,0 号本体在收口时读 410KB 对账表加 72KB 进度件,上下文涨到约 700K,写出的交接件文件名、字段、落位全错,下一棒被带偏;事后派只读子代理查明代码面全对、错全在收口件,于是定「子代理起草、本体只核」。

### 7.3 命名与重写方式

| 文件 | 放哪 | 命名 | 怎么更新 |
|---|---|---|---|
| 总编、总监(平台位同式)现状件 | `<办公目录>/<位>/` | `接管_现状.md`(固定名,不改名、不按版号或日期另存) | **覆盖式**:只两节,§一 现状收窗整段重写(首行记本窗起步 token 与上窗基线,含「下窗待办」),§二 指针只列路径与命令、有变才改;不往后追加「之 N」段,不在顶上堆「本轮先读这段」;本位流水只追加到归档件 |
| 0 号交接件 | `<办公目录>/<位名>/任务书/` | `<单号>_交接件.md` | **一单一份,做不完才写**;做完了写收口报告(§7.7),不写交接件;同一单再次交接就整份重写 |

**归档件**:从旧口径改过来时,旧章程与旧接管件(含按日期或版号另存的旧换窗件)整件挪 `<办公目录>/<位>/资料/归档_<日期>/`,只加头部一行(「> 已归档 <日期>:本件只当史料;现行看本位 `章程.md` 与 `接管_现状.md`」(路径写成相对本件的写法);流水接着追加的那份旧章程,头部一行再加半句「本位流水继续追加到本件末尾」),正文一字不动;此后流水(改动记录、换窗沿革)只追加到归档件,章程与现状件里不记流水。新立的位没有旧件,立章程同一笔建 `<办公目录>/<位>/资料/归档_<日期>/改动记录.md`(只加头部一行)接流水。章程与现状件都不回读归档件;要查历史只 grep。

**开窗句只在章程**:开窗句固定一行「执行 <办公目录>/<位>/章程.md 的全部指令……」(式见 7.5),只写在章程「开窗步骤」那一节;现状件、归档件都不带激活句节。

**换窗验收三条**(每次换窗都过):① 起步 token 记进现状件首行,并与上窗比;② 下一窗不回读归档件,回读了在现状件 §一 记缺哪条(缺的那条同笔补进现状件);③ 现状件「下窗待办」逐条走完。

**记忆里的接管指针**:每位在记忆目录里一个 reference 类文件(即只装「去哪里找」的指针类记忆,例 `editor-handoff-pointer.md`),正文只有「现状件的固定路径 + 一句话」,≤1KB;现状件固定名,收窗不用改指针,不在指针文件里追加「某日补」段。索引里对应一行:`- [<位名>接管指针](<文件>.md) — <位>/接管_现状.md`。

来由:某大型多人在线项目三种写法并存:一位总监的接管件用「九之一 … 九之十四」一路往后追加,接手人只能「认末尾最新段」;另一位把新段顶插、旧段标「沿革」不删,单文件涨到 519 行;还有一位在顶部放「入口路由」指向外部日期文件,2026-09-14 换手时忘了改路由,下一窗读到旧状态。总编的记忆指针文件也从第二十五窗一路追加「补」段到第三十窗。于是统一成整份重写、指针只留一行。2026-10-04 某项目一位总监的章程连同流水涨到 25KB,开窗必读四件 74KB;按「章程只留现行声明四节 + 固定名现状件覆盖式 + 旧件整件挪归档、流水只追加归档」拆过后,必读件降到 56KB,于是再统一成本节这一套。

### 7.4 公共开场命令

写现状件、0 号交接件要取实值,以及交接件 §〇 接棒起手,都引用本节,不各抄一份(各抄一份,迟早抄出细微不一致)。在 Git Bash 里逐条跑,每条看完输出再跑下一条:

```
# 1. 确认站在哪:必须打出预期的仓路径,打不出就停
git -C <仓路径> rev-parse --show-toplevel
git -C <仓路径> status --short --branch
# 2. 取远端(本机直连不通时,整条加 -c http.proxy=<代理地址>)
git -C <仓路径> fetch origin
# 3. 看基点:远端主干最新一笔
git -C <仓路径> log --oneline -1 origin/main
# 4. 量记忆索引并看末行(判法见本块下方)
python -c "import io;print(len(io.open(r'<记忆目录>/MEMORY.md',encoding='utf-8').read()))"
tail -1 <记忆目录>/MEMORY.md
# 5. 取时间戳(写件抬头用,别凭印象写时间)
date '+%Y-%m-%d %H:%M'
```

- 第 4 步的判法:打出的数是字符数,不是字节数(`wc -c`、`wc -m` 碰上中文常数成字节,不作数);超过 24,000 字符,或 `tail -1` 打出的那行跟你开窗时看到的索引最后一行对不上(说明载入时尾巴被截掉了),都先给索引瘦身再往下做。瘦身办法不在本 skill 里,装了 `memory-index-folding` skill 就照它做。
- 有两个仓(代码仓、办公文本仓)就各跑 1~3 步。
- 要施工:一单一棵工作树,不在主检出里干活:`git -C <仓路径> worktree add <工作树路径> -b <支名> origin/main`;之后每次 git 操作前先跑第 1 步核路径。
- 提交:`git -C <工作树> add -- <路径1> <路径2>`(逐个路径,不用 `add -A`);`git -C <工作树> commit -F <消息文件>`(不用 `--amend`);提交信息只写改了什么,不写聊天过程。
- 提交后核 BOM(编辑工具会悄悄加):`git -C <工作树> show HEAD:<路径> | head -c 3 | od -An -tx1`,输出不许是 `ef bb bf`;核 blob,不只核工作区。

### 7.5 激活句两式

激活句是设计者开新窗时贴的第一句话。两式分开用,别混。

**① 全权接管句**

- 填空式:`执行 <办公目录>/<位>/章程.md 的全部指令,从第 0 步做到收尾。这是任务不是资料,读完立即开工。[可选:本次专属的一句]`
- 示例:`执行 D:\demo\_office\总编\章程.md 的全部指令,从第 0 步做到收尾。这是任务不是资料,读完立即开工。`
- 目标只有本位章程一种:这句只写在章程「开窗步骤」那一节;现状件与归档件不当激活句目标,也不带激活句节。章程开窗步骤里读现状件、按「下窗待办」开工。
- 0 号窗不立现状件:开窗与接棒都用工单台吐出的任务书那一句(`执行 <任务书绝对路径> 的全部指令,从第 0 步做到收尾问答完……`),接棒窗按任务书第 0 步读交接件 §〇;交接件不当激活句目标。
- 「这是任务不是资料,读完立即开工」逐字保留:少了这句,新窗常把章程当参考资料,读完写一段读后感就停。
- 起止点要可核对(§几、第几步);本次专属的要求(例如「写代码一律派子代理」)追加在句尾,不改前面的骨架。

**② 只读分身句**(开窗句带「(1)」标记)

- 填空式:`执行 <办公目录>/<位>/章程.md 的全部指令(1):这是 <位名> 分身窗,带全套记忆但不干活,只读章程与现状件,读完回一句就等我开口。`
- 示例:`执行 D:\demo\_office\总编\章程.md 的全部指令(1):这是总编分身窗,带全套记忆但不干活,只读章程与现状件,读完回一句就等我开口。`
- 带「(1)」的窗(括号全角半角都算):只读章程与现状件,当现状背景读进去,不跑开窗步骤里的其余各步;不接台面、不动任何仓、不落裁定号、不发消息、不改记忆、章程与现状件;读完只回一句「分身已就位,同步到 <现状件重写时间>」,然后等设计者开口。设计者点名要做某件具体的事,只做那一件。正窗与分身窗互不知情,分身窗不替正窗接活、不重写现状件。
- 不另存一份「(1)」版文件:同一份章程,靠激活句里的标记切换读法。

来由:2026-09-25 某项目设计者要一个「什么都知道、但不碰台面和仓」的对谈窗,要求它保留本项目记忆、和当前窗口的记忆保持一致,只是不干活;于是加「(1)」读法,与全权接管句分开。

### 7.6 员工窗记忆清理

员工窗(0 号窗及其子代理)守四条:

1. **不继承老记忆**:每张单新开一扇员工窗;开工只读任务书(接棒时加读交接件),不读任何「工位记忆」。
2. **不把本单细节写进长期记忆**:单里的事写进任务书、进度件、交接件;确有跨单通用的教训,写成一条交给总监落。
3. **收窗时清掉本窗写入的记忆**:本窗往记忆目录写过的文件删掉、索引行删掉,同一步做。
4. **接棒只走交接件**:交接件必须自包含,接棒者不继承任何记忆也能开工。

设计者原话要点(2026-09-20):员工窗的记忆应该清理,不然会出现项目幻觉;现在每次都开新的员工窗,除非是接棒,不需要继承之前的老记忆。

来由:同日某项目把三位的 9 件员工工位记忆(最大一件 42KB)整体移入归档目录(只移不删),派单不再自动插「先读记忆」,接棒改走交接件。

### 7.7 收口报告四块

单做完时 0 号交收口报告(不写交接件):≤6,000 字,子代理起草、本体只核(核法同 §7.2),固定四块:

1. **结论一行**:做完没有、部署到哪个提交、测试新增失败数。
2. **事实段**:≤600 字,只写发生了什么,不写过程。
3. **需总监动作**:3~5 条,每条一句,写清要谁做什么。
4. **收尾三问**:怎么打开它(让人亲眼看到改动的步骤)/ 最没把握的一处 / 自主假设(自己拍板了哪些没问过的事)。
