# 轻闸骨架 · 甲类大型单施工主窗工序(与 短书骨架.md 配套)

给施工主窗:甲类大型仍用短书 + 轻闸,由总监主窗直派施工员 / 读件员 / 审计员(单窗);执行员(困难档子代理或独立窗)只在回退线触发后用。任务书里写「照本骨架」的节,按下面对应节做;任务书写死的以任务书为准,偏离逐条记进收口报告。

## §0 开窗起手
- 接通道:`{{工单台命令}} receipt <单号>`,必须原样打出本单;打不出就停,报错原样写进本单对话线。
- 开工作树:`git -C {{代码仓路径}} fetch {{代码托管远端}}`,再 `git -C {{代码仓路径}} worktree add {{工作树根目录}}/wt-<员工名>-<单号尾号> -b <分支> {{远端主支}}`;窗本体不 cd 进树,命令一律 `git -C <树路径>`;认领:`{{工单台命令}} claim <单号> --by <员工名>`,已认领的报「已认领」即算过。
- 读收件:`{{工单台命令}} inbox --slot <位名> --for <员工名>`,开工、并线前、上服前、收口前各一次;参数以 `-h` 为准。
- 红线:编号与契约不越段(裁定号只由总编登、工单号只由工单台发);在跑属主件不并行改;只动任务书 §三点名的路径,范围外停在边界报一句。
- 待答题:≤5 题,一题一行写 A / 后果、B / 后果、本单先按哪个做;不等答,按默认做完。
- 偏离项:任务书与本骨架不同处逐条记一行;觉得骨架本身该改,不在任务书里改,记一行交总编。
- 四档:顶级主窗自做、不派子代理;困难做复杂施工、完整审计与起草;日常做普通施工、轻审;轻量做扫盘读件。四档的具体模型映射由 {{拍板人}} 另行给定;派单、任务书、台面只写档位词,模型照该映射实填,{{拍板人}} 改口走当日口径,窗口自报。开窗指令从工单台取(认领 / 执行任务书两行),不手写、不另加提示词。
- 第一段回话四行(报完直接开工,不等回话):本窗平台 / 本平台子代理能开的模型与档位 / 权限模式(看不到写「本窗看不到,请看窗口状态栏」)/ 本窗模式与第一个要派的子代理。

## §1 出题底数与施工
- 底数(任务书 §四)用前复核;核出与任务书不符,以真源为准照做,收口报告记一行,不停车。
- 施工按任务书 §三白名单逐项做;超出任务书的改动留痕三处:本单对话线留言(拍板原话逐字带时刻)、提交信息(只写改了什么与依据)、收口报告事实段一句。
- 测试分档:build 一次 + 任务书点名用例各跑一遍;完整套只在并线头组合树跑。

## §2 并线
- fetch 后在 {{远端主支}} 最新头上重建组合树;解冲突分三类:自己的按本单改、别人的原样留、两边都要一行不丢。
- 先构建、按 §1 分档测试、再逐名对账,都过了才并;推主支三次失败停车、不强推;并完记「已并 <主支新头> 测试 <通过数/失败数>」。

## §3 审计(写明档位)
- 审计档位由总监在任务书 §五写明:甲类大型与改账本 / 协议 / 持久化 / 并线上服脚本的派完整审计,其余轻审;审计件写「核了什么」「问题与结论」两节,附任务书要求的计数。
- 施工主窗不自审;审计子代理独立起,不共用施工上下文。

## §4 收口(四块 ≤ 6,000 字)
- 写四块:做了什么与并线号 / 判据逐条自核 / 未做与偏离 / 要拍板人答的;收尾三问 ≤300 字。
- 产出上限:进度件 + 收口报告 + 总监派的审计件,可选 1 件,合计 ≤4 件。

## §5 上服与 settle
- 有上服的跑本单的生产脚本,只在本模块做完那一次;没有上服,任务书写「不适用」。
- 留闸 · 部署互斥锁:同一部署动作全项目同时只有一窗能跑;见别单的锁在,记一行等它跑完再上,等的是那次部署动作,不是别单状态。
- 留闸 · 部署前祖先核:部署前核部署头是现网正在跑的头的祖先;核不上,照实报告、不部署、不绕。
- settle:`{{工单台命令}} settle <单号>`,参数以 `-h` 为准。

## §6 交集与不做
- 与同期单的交集小表:单号 / 交集文件 / 谁先 / 要对方做什么;后并者并先并者头,不 rebase。
- 不做:不动别单目录与文件;不做任务书没派的活;做不完的只写「事件还没发生 / 归别位」两类之一。

## §7 未核清单
- 开工时派扫盘子代理核 3~8 条,结果记进度件;核出与任务书不符按 §1 处置。
