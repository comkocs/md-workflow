# 共用检出与工作树 · 精简步骤

这里列的是步骤与判法,每条都能直接照做。尖括号 `<…>` 是运行时现填的值。

## 一、开工前

1. 接手前先查远端有没有同前缀的支:`git ls-remote {{代码托管远端}} | grep <前缀>`;支在就是有人在做,不管任务记录上怎么写。疑似两扇窗在做同一件事,立刻停下问{{拍板人}}定属主。
2. 一单一棵工作树,不在主检出里干活:`git -C {{代码仓路径}} worktree add {{工作树根目录}}/<单名> -b <支名> {{远端主支}}`(或从具体提交号拉)。任务书写死路径与支名,不写「cd 到某仓」。
3. 每次 git 操作前先核站在哪:`git -C <工作树> rev-parse --show-toplevel` 打不出预期路径就停。派并行子代理时各给一棵树,提示词开头就要它先跑这条。

## 二、共用检出上的六条

有人和你共用同一份检出时一律守;真做到一单一树、没有任何共用检出时可省。

4. 回退前先 `git status --porcelain`:有不是自己的未提交件就不跑 `reset --hard`,改用 `merge --abort` 或挪到独立临时树;要回退只用 `reset --mixed`。数「有没有人在干活」先按源码扩展名过滤。
5. 提交一律带路径:`git -C <工作树> add -- <路径1> <路径2>` 逐个加,不用 `-a`、`add -A`;`git -C <工作树> commit -F <消息文件>`。
6. 共用支上不用 `--amend`,它会顶掉别人刚提交的一笔。
7. 推送被拒,先看 HEAD(`git log --oneline -3`)是不是自己那一笔,不直接 reset 或 rebase。
8. 建临时验证树用提交号、不写支名:`git worktree add <路径> <提交号>`(游离头)。已经写了支名建树、临时树里一合并就把共享支带着往前走、共用检出的状态冒出一批「已删除」时,这样补救:先在临时树里跑 `git checkout --detach`,把支让出来;再到共用检出里跑 `git reset --mixed <原头>`(`<原头>` 是出事前支所在的提交号,`git reflog <支名>` 里查得到),支与索引拨回原处,工作区不动;看到 `git status` 里那批「已删除」消失、`git log --oneline -3` 的头对了,再按第 9 条做真并。
9. 合并在临时树里做完、核完,共用检出上只做最后一次真并。

## 三、提交后与验证中

10. 提交完要查进了仓库的那一份,光看工作区的文件不算数:跑 `git -C <工作树> show HEAD:<文件> | od -An -tx1 -N3`,它打出已提交内容开头的 3 个字节;打出 `ef bb bf` 就是带了 BOM,不合格。提交信息只写改了什么。
11. 耗时的实机验证前后各记一次运行代码指纹(提交号、产物哈希),两次不一致就判作废重跑;回报带前后两次指纹。
12. 清理共享检出前先 `git status`,不是自己留下的改动一律不动。

## 四、常驻服务与长跑进程

13. 给别的任务长期用的本机服务、测试夹具、长跑探针,起在它自己单独命名(名字带用途)的工作树上,不和并线、构建、跑测试的树共用;任务书写明路径。
14. 构建突然全报「文件被占用」:先看报错点名的进程号与路径是不是这棵树里的常驻进程,是就把进程挪到独立工作树,不当代码错修。

## 判做对了

- 任意两个并行任务的 `--show-toplevel` 输出都不同。
- 每一笔提交的文件清单只含自己点名的路径。
- 并线用的树里没有任何常驻进程。
