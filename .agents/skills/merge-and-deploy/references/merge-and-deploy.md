# 并线上服

触发：0 号完成修改、准备并线时执行。本件是并线上服执行顺序的单一真源；规范约束及理由见宪法和对应种子，角色与任务模板链接本件。没有线上服务时，仅部署相关步骤不适用，并线、身份、测试、回收照常。

1. **重建组合树。** fetch 最新远端主干，在其上 rebase 或 merge 本单分支；自己的冲突自己解，他人的改动原样保留，两边都要的内容一行不丢。
2. **核未部署提交。** 从线上读实际运行头，列出“线上头..远端主干”中他人已推未部署的提交及责任方；有则在本位工单对话线通知本位总监，由相关总监协调并等结果，不径自替别人首服。部署前重新核一遍。
3. **核工作树身份。** 按种子 7.19 第 2 条开启 `extensions.worktreeConfig`，用 `git config --worktree user.name <员工名>` 与 `git config --worktree user.email <员工邮箱>` 设置身份并回读；不改仓本体身份。
4. **先构建。** 用部署所需构建配置 build 全部工程，保存命令与原样退出码，全部 rc=0 才继续；构建红先修，不以测试绿代替。
5. **核基点并选测试套。** 每个基点头只测一次，原始结果落共享盘，后续按头复用。判据为“红集 ⊆ 基点红集，新增红 = 0”；抖动集只标注、不作闸。单窗在组合树按改动面跑一次：纯客户端跑客户端套，纯服务端跑服务端套，两边都碰或动协议跑全套；任务书未点名按宪法闸 27③跑全套。批次模式各窗只跑本单点名测试，最后上服窗在最终组合树跑一次完整套。逐名对账，删或跳的测试逐项说明。
6. **做提交卫生。** 核改动文本在提交 blob 里的首字节，确认无新增 UTF-8 BOM；按白名单逐个提交，不带日志与压缩包，不应入仓的产物移出提交后再核。
7. **推送并配对。** 推送待部署提交并回读远端；项目有两仓时，核两仓配对引用一致，任一不一致先修复；无配对仓则不触发配对检查。
8. **部署前互通。** 在本位对话线及已授权的同期窗口通道告知“准备上服，部署头 <完整提交号>”，核交集与先后安排；跨窗对象与送达按宪法闸 34。
9. **执行祖先闸。** 核“线上头 ⊆ 部署头 ⊆ 当时远端主干”，逐项保存 `git merge-base --is-ancestor <线上头> <部署头>` 与 `git merge-base --is-ancestor <部署头> <远端主干>` 的退出码；机器闸红了不许绕，回到组合树修正再核。
9.1 **配置面预检。** 改了启动时导入的配置 / 冷表键目录的单,部署前先算“现网键集 − 新目录键集”;差集非空说明现网有本单退役的旧键,先带备份精确摘除再部署;没改配置面的,记一行“免预检”。
9.2 **上服预告。** 上服前在线上测试员(人或 AI)的通道预告“约 N 分钟后上服,部署头 X”,不等回音;没有测试员的不适用。
10. **显式部署配置。** 会重写配置的部署脚本，其默认值会覆盖线上配置；先记录部署前值，执行时必须显式带线上应保留开关的旗标，再核有效参数。改过服务器部署脚本的，按种子 7.25 核目标机脚本版本后再部署。
11. **部署后回读。** 从运行环境核六样：①实际头与版本指向；②进程已激活且启动时间晚于部署开始；③端口监听与命令行；④产物大小与目录非空；⑤冷表与版本戳；⑥部署头是远端主干祖先，否则立即推送缺失提交，再 fetch 复核，分叉按种子 7.19 第 3 条处理。远端主干已前进但包含部署头仍成立，不以本地已有代替远端事实。回读不符先修复，不能写完成。
12. **确定审计范围。** 先按 first-parent 剔除夹层提交，列清本单改动与并入的他单改动，以此划本单审计归责范围；最终组合树测试与部署清单仍覆盖带入的他单改动。
13. **回收工作树与分支。** settle 前按种子 7.19 第 4 条保全成果，回收本单工作树和已合并分支，不碰他人的树与分支。
14. **锚定仓外件。** 带仓外件的单，settle 前把 SHA256 写进打包清单，打包员出包前逐条核包与清单一致。
15. **交接顶级审计。** 并线后由模块总监派一道顶级审计，模型能力按种子 2.10；不把该审计另加成 settle 的前置。审计件首行固定为“幻觉 N / 笔误 N / 漏做 N / 未核 N / 环境限制 N”。
